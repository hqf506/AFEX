# A2.3H Operator Submission and Redaction Guide

## Submission register

| Provider | Channel/page | Subject | Message source |
|---|---|---|---|
| Supabase | Authenticated Support case appropriate to database/pooler questions | Transaction Pooler support for isolated PostgreSQL LOGIN, role activation, cleanup, and Vercel Node clients | `A2.3H-SUPABASE-SUPPORT-REQUEST.md` |
| Vercel | Authenticated project Support channel | PostgreSQL TCP, pooling, lifecycle, IPv6, and secret-rotation guidance for Node 24.x Functions | `A2.3H-VERCEL-SUPPORT-REQUEST.md` |

Provider interfaces may change. If no applicable channel exists, record `NOT_AVAILABLE`; do not send through a public forum.

## Allowed metadata

Include capture UTC, case ID, provider/product/plan labels, PostgreSQL/Node version, pool mode and port, pool size, maximum-client limit, and sanitized question IDs. Include project reference only if strictly required in a provider-secured case field.

## Mandatory redaction

Remove passwords, usernames where unnecessary, database/connection URLs, hostnames, credentials, API/JWT/access/refresh tokens, service-role or anon values, certificates, environment values, IP allowlists, customer/tenant/order/payment data, payloads, Production idempotency keys, and raw logs containing any of those values.

## Evidence capture

- Record submission and response timestamps in UTC.
- Prefer safe text transcription; crop screenshots to the exact answer.
- Store raw responses only in the approved ignored evidence location.
- Normalize a redacted copy using the A2.3E evidence schema.
- Hash retained evidence and record reviewer identity by organizational role.
- Suggested local location: `database-reconciliation/core-v2/P2D/evidence/A2.3H-provider-<UTC>/`.

## Answer classification

| Classification | Meaning | Gate treatment |
|---|---|---|
| CONFIRMED_SUPPORTED | Scoped provider answer explicitly supports the requirement | Provider prerequisite may pass; runtime test still required where specified |
| CONFIRMED_UNSUPPORTED | Provider explicitly rejects a required semantic | Critical gate fails; evaluate fallback |
| DOCUMENTATION_ONLY | Answer cites general documentation without scoped guarantee | Supporting evidence only |
| AMBIGUOUS | Conditional, incomplete, or scope unclear | Remains blocked |
| REQUIRES_RUNTIME_TEST | Provider states behavior must be observed | Proceed only to reviewed isolated test design/execution |
| CONFLICTING | Provider sources disagree | Stop and reconcile before testing or design reliance |

Do not edit an answer to make it conclusive. Preserve provenance and record interpretations separately.
