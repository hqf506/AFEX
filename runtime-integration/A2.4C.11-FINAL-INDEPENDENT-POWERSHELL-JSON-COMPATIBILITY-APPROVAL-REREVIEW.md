## Duplicate-key guard findings

Decision: `DUPLICATE_KEY_GUARD_APPROVED`.

`Get-TopLevelJsonPropertyNames` tokenizes quoted JSON strings and structural punctuation, tracks nesting depth, captures only strings in top-level key position, and decodes each key through the platform JSON parser. Grouping occurs on decoded names, so literal and Unicode-escaped forms of the same key collide. Independent adversarial evaluation confirmed rejection of duplicate required keys, Unicode-escaped duplicates, differently escaped duplicates, and duplicate non-required keys. Property-like text containing braces, colons, commas, quotes, and key names produced no false positive; nested keys and empty structures remained outside the top-level inventory. Malformed JSON failed closed during parsing.

The reviewed guarantee is deliberately limited to duplicate keys in the top-level evidence object. Nested evidence is emitted by the pinned authoritative harness and is validated through the reviewed schema and source hash; this guard makes no broader generic nested-duplicate claim.
