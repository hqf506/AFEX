# A2.4B.5E Read-Only Audit Interpretation Contract

The audit reads only PostgreSQL catalogs/settings, begins `READ ONLY`, emits a completion marker, and rolls back. It reads no business relation or customer, tenant, order, or payment value.

Catalog evidence can prove observed identity, attributes, memberships, ownership, ACL/settings rows, extensions, and apparent effective schema privilege at capture time. It cannot prove that Supabase supports a future action, that the SQL editor uses the same identity as psql, that CREATE/ALTER/ownership transfer will succeed, or that Supavisor runtime semantics are safe.

Missing rows, missing marker, nonzero exit, unexpected duplicate role identity, insufficient catalog visibility, or ambiguous managed-role state is `INDETERMINATE` and blocks mutation design. Apparent CREATEROLE or CREATE privilege is necessary evidence only, never execution authorization.
