These are existing administrative boundaries. None authorizes reuse for Core V2 acquisition.

## Sharing and isolation conclusion

- Browser client: shared within a browser realm and bound to mutable user Auth state.
- Server user client: request/cookie scoped at the SDK layer, but PostgREST hides physical connection lifecycle.
- Admin client: process-shared generic service-role SDK.
- Order route client: request-local SDK object, but not a request-exclusive PostgreSQL session.

No current path proves a dedicated application LOGIN, transaction-bound role activation, `RESET ROLE`, `DISCARD ALL`, or connection-return sanitation. Therefore every existing construction path is rejected as the future trusted Core V2 command client.
