# A2.3 Connection Lifecycle Contract

Status: future normative lifecycle; implementation blocked

## Lifecycle

| Step | Expected state | Failure action | Safe event | Scope / cleanup |
|---:|---|---|---|---|
| 1 | Gate enabled and exact environment/topology/attestation versions present | Fail before connection | `trusted_config_rejected` | Process startup/request preflight |
| 2 | Acquire bounded connection using dedicated LOGIN secret | Return unavailable; no fallback | `connection_acquire_failed` | Pool checkout |
| 3 | Begin explicit transaction on one pinned backend | Destroy/quarantine on ambiguous state | `transaction_begin_failed` | Transaction |
| 4 | Prove `session_user` and pre-activation `current_user` equal approved LOGIN | Roll back, destroy, critical alert | `identity_precheck_failed` | Transaction query |
| 5 | Activate hard-coded `afex_core_runtime` using approved transaction-local mechanism | Roll back; do not call function | `role_activation_failed` | Transaction-local |
| 6 | Prove `current_user=afex_core_runtime`; prove not postgres/service/authenticator | Roll back, destroy, critical alert | `role_activation_verified` | Transaction query |
| 7 | Apply only frozen transaction-local timeouts/settings | Roll back | `transaction_policy_applied` | Transaction-local |
| 8 | Execute exact P2D.20 signature with sealed values | Classify DB result/error; no arbitrary retry | `acquisition_called` | Single allowlisted statement |
| 9 | Validate column count, types, disposition and identity bindings | Roll back, invariant alert | `acquisition_result_validated` | In process before commit |
| 10 | Commit for a validated result, otherwise roll back | Treat lost commit response as unknown | `transaction_end` | Transaction |
| 11 | Prove transaction ended and `current_user` restored to LOGIN | Destroy on any doubt | `identity_postcheck` | Fresh safe query only if topology permits |
| 12 | Clear/verify session state required by approved pool contract | Destroy on cleanup failure | `connection_cleanup_verified` | Session/pool return |
| 13 | Return safe connection or close it | Never return unverified connection | `connection_released` | Pool lifecycle |
| 14 | Emit stable result/error and reconcile unknown outcome with same key | No dual write or legacy fallback | `trusted_call_complete` | HTTP/application |

## Proof points

- Expected LOGIN identity is compiled/configured from a reviewed allowlist, not request input.
- Runtime role target is a constant; no arbitrary role API exists.
- Pre-activation assertion rejects postgres, service_role, authenticator and every unexpected identity.
- Function execution is unreachable if activation or proof fails.
- P2D.20 result is bound to the same actor, tenant, branch, key fingerprint and canonical payload contract.
- Cleanup is checked on success and all error paths.
- A quarantined connection cannot re-enter the pool.

## Logging boundary

Events contain correlation/request IDs, pseudonymized scope IDs, attempt number, pool/client type, stage duration, expected/observed identity category, disposition and stable SQLSTATE category. They never contain URL, password, token, PIN, raw key, payload, projection, customer/payment data, raw SQL or unrestricted diagnostics.

## Shutdown and concurrency

Each request owns its checkout and transaction. Concurrent requests share only the bounded pool, not a connection or context. Shutdown stops new checkout, waits a bounded drain, rolls back/terminates remaining transactions, destroys unverified connections and records unknown outcomes for same-key reconciliation.
