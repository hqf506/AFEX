# A2.5 DCA O10-A Operation and Provider Disposition

Binding disposition: `VERIFICATION_AND_INTENT_ONLY`. Generic and operation-specific Docker mutation executors are permanently `PROHIBITED` inside this engine. Every template terminates at `VERIFIED_NON_EXECUTABLE_INTENT`.

## PD6G operation inventory

The authority path requires one read-only identity/state gate followed, under separate future authorization, by four ID-bound candidates: stop the verified PgBouncer container; remove that same verified stopped container without force; disconnect the verified PostgreSQL container ID from the verified network ID; and remove the verified zero-consumer network ID. Each candidate has observable pre/post states, but Docker cannot join the durable-authority transaction. Crash, timeout, or lost response can therefore leave an unknown outcome. Blind replay is prohibited and recovery requires fresh observation plus a new authorization.

Explicitly prohibited operations are broad Compose down, force removal, every prune operation, image removal/retagging, and volume removal. Image, repository configuration, evidence, secret, Git state, and every volume remain retained.

## Exact protocol requirements

Every candidate binds actor, exact action, target, scope, immutable target ID, daemon/context/host identity, repository base, pre-state, desired post-state, one-use authorization, durable intent, current lineage/revocation evidence, and trusted time. Precondition and postcondition evidence are independent. `BEFORE_MUTATION` interruption cancels; post-request crash or lost response becomes `UNKNOWN`. Neither state permits replay. Recovery requires new authorization and durable reconciliation evidence.

## Provider selection checklist

| Category | Required disposition | Selection evidence required | Prohibited fallback |
|---|---|---|---|
| Host provenance | `REQUIRED_EXTERNAL_AUTHORITY`; unselected | Authenticated H3-D binding, current local binding, freshness, revocation, replay resistance, trust owner | Local names, daemon/context identity, or cached claims |
| Threshold approval | `REQUIRED_AUTHENTICATED_THRESHOLD_PROVIDER`; unselected | Exact principal authentication, threshold proof, final-digest subject binding, immutable attestations | Digest equality or unauthenticated signatures |
| Trusted time | `REQUIRED_AUTHENTICATED_TIME_PROVIDER`; unselected | Subject-bound UTC proof, chronology, freshness limits, revocation/failure behavior | Local wall clock alone |
| Lineage/current pointer | `REQUIRED_APPEND_ONLY_CURRENT_AUTHORITY`; unselected | Atomic current pointer, append-only events, freshness and historical audit | Embedded or cached currentness |
| Revocation | `REQUIRED_CURRENT_REVOCATION_AUTHORITY`; unselected | Authenticated current status, propagation bound, fail-closed outage policy | Missing/unknown treated as current |
| Execution authorization | `REQUIRED_ONE_USE_AUTHORIZATION_PROVIDER`; unselected | Exact scope binding, atomic issue/reserve, expiry, revocation, replay rejection | Terminal approval inferred as execution authority |
| Durable consumption/audit | `REQUIRED_CRASH_CONSISTENT_STORE`; unselected | Unique intent, atomic reservation, crash-consistent terminal result, recovery queries | Memory-only or best-effort logging |
| Docker observation | `REQUIRED_READ_ONLY_RUNTIME_ADAPTER`; unselected | Exact immutable IDs, complete state, daemon/context/host continuity, bounded freshness, partial-read rejection | Names/labels alone or stale inventory |
| Docker mutation | `OPERATION_SPECIFIC_ONLY`; no executor | Independent proof for each exact action, pre/postcondition and crash/recovery protocol | Generic executor, blind retry, O10-B substitution |

No provider is selected, simulated as production, or configured by this package.
