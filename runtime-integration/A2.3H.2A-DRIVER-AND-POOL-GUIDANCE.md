# A2.3H.2A Driver and Pool Guidance

## Driver ADR decision

`PG_PREFERRED_PENDING_RUNTIME_TESTS`

Vercel explicitly supplied a node-postgres integration pattern and recommends a global Pool with platform lifecycle attachment. This makes `pg` the preferred candidate for the future ADR, but selection is not final until Node 24, transaction checkout, cancellation, preparation mode, error handling, observability, cleanup, and narrow-interface tests pass.

## Package impact

| Package | Classification | Boundary |
|---|---|---|
| `pg` | FUTURE_REQUIRED | Required if the Vercel transaction-pool topology is finally approved; installation remains blocked pending ADR and separate approval |
| `@vercel/functions` | FUTURE_REQUIRED | Required for `attachDatabasePool` under the selected Vercel lifecycle model; installation remains blocked pending separate review |

Neither package is installed or added to package metadata in A2.3H.2A.

## Future configuration guidance

- Create one process-global Pool outside request handlers.
- Use only the approved Supabase transaction-pool connection configuration, never direct PostgreSQL for normal Runtime traffic.
- Integrate the Pool with `attachDatabasePool` so Vercel can manage idle connections before suspension.
- Use a short idle timeout; approximately 5000 ms is a provider recommendation, not yet a frozen AFEX constant.
- Disable or avoid persistent prepared statements and all transaction-pool-incompatible session features.
- Use a bounded maximum greater than 1; do not invent the final number until capacity evidence is complete.
- Checkout exactly one client per command transaction and release it in a guaranteed lifecycle path.
- Destroy/quarantine connections after uncertain cancellation, cleanup, or transaction state.
- Expose only domain-specific acquisition operations; never expose generic query text, arbitrary SQL, or arbitrary role targets.
- Keep Core V2 hard disabled. No credential loading, socket, Pool, P2D.20 call, route change, dual write, or feature activation is authorized yet.

## Required ADR comparisons

The final ADR must still compare `pg` against postgres.js for Node 24 compatibility, generic-query exposure risk, transaction pinning, `SET ROLE`, prepared-statement control, cancellation, serverless reuse, metrics, bounded shutdown, and testing. Vercel preference is strong input, not a substitute for AFEX review.
