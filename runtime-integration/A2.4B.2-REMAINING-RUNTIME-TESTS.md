# A2.4B.2 Remaining Runtime Tests

Status: TEST INVENTORY; EXECUTION NOT AUTHORIZED

## A. Removed

These A2.4B.1 role-switch tests are cancelled under direct EXECUTE:

- `SET LOCAL ROLE` activation.
- `current_user` transition into and out of `afex_core_runtime`.
- Commit/rollback role-reset testing.
- Membership revocation as the application authorization switch.
- Role-target contamination and arbitrary role-switch rejection in the application path.

Zero membership and absence of SET capability remain SQL attestation requirements, not runtime activation tests.

## B. Still mandatory

| Test | Mandatory pass condition |
|---|---|
| Backend PID consistency | One backend serves every statement within each explicit transaction used by the harness. |
| Direct entrypoint invocation | The dedicated LOGIN can invoke only the exact test/approved entrypoint through transaction pooling and receives the exact typed result. |
| Prepared-statement prohibition | No named or persistent preparation is configured, emitted, or retained. |
| Advisory transaction lock | Correct contention and release occur at commit and rollback; timeout/disconnect outcomes are classified. |
| Cancellation and timeout | Bounded termination occurs; uncertain clients are destroyed; outcome reconciliation uses the same key. |
| Abrupt disconnect | Server transaction terminates or the result is classified unknown; no connection is reused without proof. |
| Unknown commit outcome | No replacement key, dual write, or legacy fallback; same-key reconciliation produces one safe outcome. |
| Pool exhaustion | Bounded backpressure and timeout occur without connection storm, starvation, or secret leakage. |
| Connection quarantine | Every ambiguous, failed-cleanup, protocol, timeout, or disconnect client is destroyed and excluded from reuse. |
| Credential rotation | New short-lived credential succeeds, old credential fails after revocation, and no fallback exists. |
| LOGIN disablement | Disabling the disposable LOGIN blocks new use and existing sessions follow the reviewed termination policy. |
| EXECUTE revocation | Revoking the exact grant immediately prevents new entrypoint calls after connection/session handling is applied. |
| Object-access denial | Table, column, sequence, schema CREATE, and ownership operations fail. |
| Other-function denial | Internal helper, overloads, and unrelated functions cannot be executed through any direct/effective path. |
| Sequential reuse | No transaction, GUC, prepared state, result, correlation marker, or identity anomaly crosses checkouts. |
| Concurrent isolation | Results and synthetic markers remain bound to the correct logical request under bounded concurrency. |
| Observability | Safe events, timings, pool counters, outcomes, exit codes, quarantine, and cleanup evidence are complete without secrets. |

The production P2D.20 entrypoint must not be invoked during a harmless isolated test unless a later phase separately authorizes the exact non-business strategy and proves no business mutation. A harmless structurally analogous SECURITY DEFINER test entrypoint is preferred for topology and privilege tests.

## C. Optional defense in depth

- Repeat backend pinning and contamination cases across warm-process and controlled cold-start boundaries.
- Repeat with multiple bounded pool sizes within the approved capacity envelope.
- Extended sequential soak beyond the activation-blocking minimum.
- Fault injection at additional safe client lifecycle boundaries.
- Independent catalog snapshot comparison before and after the disposable campaign.

Optional tests cannot compensate for failure or missing evidence in a mandatory test.

## Disposable design reconciliation

Decision: `REPLACED`.

The future environment uses one disposable dedicated LOGIN, no membership, one harmless SECURITY DEFINER test entrypoint or a separately reviewed exact production-entrypoint strategy, an explicit exact-signature EXECUTE grant, denial attestations for all other objects, short-lived credentials, complete revocation/cleanup, and Git-ignored local evidence. No business table or P2D.20 mutation is assumed or authorized.
