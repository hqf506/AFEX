# A2.3H Vercel Support Request

## Subject

PostgreSQL TCP, pooling, lifecycle, IPv6, and secret-rotation guidance for Node 24.x Functions

## Message

We are evaluating a server-only PostgreSQL client from Vercel Node 24.x Functions to a hosted transaction-pool endpoint. Browser and mobile clients would never receive database credentials.

Please answer for the applicable project plan and Runtime model:

1. Are outbound PostgreSQL TCP connections supported from Node 24.x Functions?
2. Can warm instances safely reuse pooled TCP connections?
3. What maximum or conventional per-instance pool size is recommended?
4. What happens to open connections during freeze, scale-down, cancellation, redeployment, and process termination?
5. Is outbound IPv6 supported for hosted PostgreSQL direct and transaction-pool endpoints?
6. Is outbound IPv4 guaranteed?
7. Is static egress available for this project/plan?
8. Is a transaction-pool endpoint preferred over direct PostgreSQL from Functions?
9. Are long-lived pools recommended, or should connections be short-lived?
10. How is the maximum concurrent function-instance count determined?
11. What are the effective maximum duration and memory for the current project?
12. Is Fluid Compute enabled or otherwise relevant to connection reuse and concurrency?
13. Are there restrictions on `pg`/node-postgres?
14. Which logs or metrics expose database connection errors, timeouts, cancellation, and instance lifecycle?
15. What secret-rotation workflow avoids exposing a database credential to Preview while supporting safe Production rotation and emergency revocation?

Please distinguish guaranteed platform behavior from recommendations and behavior that requires an isolated runtime test. No credential, connection string, token, project secret, or business data accompanies this request.
