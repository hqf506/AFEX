# A2.4B.1 Pass/Fail and Evidence Contract

Status: NORMATIVE TEST-DESIGN CONTRACT

## Universal decision rule

A case passes only when prerequisites, the primary observation, all identity boundaries, cleanup, evidence completeness, and artifact hashes pass. Missing, ambiguous, conflicting, contaminated, truncated, or uncleaned evidence is a failure. Tests must not auto-retry with weaker security, a different role mode, session-scoped activation, persistent prepared statements, or a replacement credential.

## Case criteria

| Test | Pass | Fail |
|---|---|---|
| B01 backend pinning | One backend PID from transaction start through its terminal commit/rollback | PID changes, cannot be observed, or transaction semantics are ambiguous |
| B02 local activation | Stable `session_user`; `current_user` equals LOGIN before, test role only during activation, and LOGIN after transaction | Activation fails, wrong identity appears, or authority persists |
| B03 commit cleanup | No role/GUC/path/lock residue on same client or later checkout | Any residue or uncertain reusable state |
| B04 rollback cleanup | Rollback completes and all state returns to baseline | Failed rollback, residue, or reuse before proof |
| B05 cancellation cleanup | Cancellation is classified; transaction rolls back; client is sanitized or destroyed | Client returns to pool while state is unknown |
| B06 timeout cleanup | Timeout is bounded; uncertain client is destroyed | Empty outcome, unbounded wait, or uncertain reuse |
| B07 disconnect cleanup | Server transaction ends and subsequent checkout is clean | Surviving transaction, privilege, lock, or ambiguity |
| B08 sequential contamination | Zero mismatches across the reviewed iteration count | Any previous-client state appears |
| B09 concurrent contamination | Every marker and identity stays within its logical client | Cross-client state, race, or unexplained observation |
| B10 advisory lock | Correct exclusion and automatic release on both commit and rollback | Broken exclusion, surviving lock, or unverifiable release |
| B11 prepared prohibition | Configuration and observations show no named/persistent preparation | Any persistent prepared state or unsupported fallback |
| B12 quarantine | Every uncertain connection is destroyed and excluded from reuse | Release, reuse, or incomplete destruction proof |

Any B01–B12 failure rejects the tested topology pending a separately reviewed correction and complete clean rerun. B02 failure does not authorize fallback to session-scoped `SET ROLE`.

## Evidence artifact set

Each run must create a unique ignored local directory containing:

1. `manifest`: artifact names, sizes, SHA-256 hashes, harness/setup versions, and case inventory.
2. `masked-configuration`: runtime version, transaction-pooler class, verified TLS-mode label, preparation disabled, numeric pool/time bounds, and credential-presence boolean.
3. `stdout`: complete sanitized normal output.
4. `stderr`: complete sanitized diagnostics.
5. `step-results`: numeric process exit codes, start/end timestamps, durations, completion markers, and pass/fail states.
6. `identity-observations`: case ID, pseudonymous client ID, backend PID, safe transaction ID where available, `session_user`, `current_user`, stage, and timestamp.
7. `contamination-matrix`: expected/observed identity and marker booleans for sequential and concurrent cases.
8. `lock-observations`: synthetic lock-case ID, backend PIDs, contention timing, terminal path, and release result.
9. `quarantine-log`: reason category, connection pseudonym, destroyed boolean, and reuse-denied boolean.
10. `cleanup-attestation`: pool drained, no test sessions/locks, credential revoked, membership removed, disposable objects absent, and final marker.
11. `review-decision`: gate mapping, failures, reviewer, decision timestamp, and approved next action.

## Evidence safety

Allowed fields are fixed test role names, case/run IDs, backend PIDs, safe transaction identifiers, timestamps, booleans, SQLSTATE, durations, pool counters, version/mode labels, exit codes, markers, and hashes.

Prohibited fields include passwords, tokens, full connection URLs, hostnames, certificates, raw environment values, stack traces containing configuration, business data, payloads, customer/tenant/order/payment/inventory identifiers, Production idempotency keys, and arbitrary SQL text.

Raw evidence remains ignored and local. Any evidence proposed for commit requires separate sensitivity review; hashes alone do not make sensitive evidence safe.
