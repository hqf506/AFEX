# A2.5 PD.6 Local PostgreSQL Evidence Design

## Architecture and authority

The harness imports the merged PD.5 `RealDriverAdapter`; it does not duplicate lifecycle, rollback, sanitation, release, or ambiguity decisions. A trusted fixture module maps closed operation identifiers to fixed unnamed query configurations. Transaction control remains in constructor-injected controls and is unavailable as borrower-supplied SQL.

## Non-network test authority

The harness authority is 46 tests with 46/46 passing and zero padding or filler. These tests are non-network harness/unit evidence only and do not prove real PostgreSQL behavior. The PD.5 adapter regression remains 66/66 passing with deterministic digest `21ea31f7bcbb4ca90e45062a3d9e93ea7f6b4e9c7ac0829ea99ba6684009bebe`. PD.6C remains unauthorized until independent review passes and is the first real Direct PostgreSQL execution tier.

Only public `pg` surfaces are allowed: `Pool`, `pool.connect()`, `pool.end()`, `client.query()`, documented event handling, `client.getTransactionStatus()`, and `client.release()`/`release(true)`. Backend PID, secret key, private transaction fields, socket/protocol internals, cancellation internals, child processes, Docker, and psql are outside the harness.

## Credential boundary

The operator must supply an explicit in-memory object with exact identity `127.0.0.1:55432`, `afex_a25_pd6`, and `afex_a25_pd6_runner`, plus a non-empty password. Unknown fields, alternate endpoints, postgres identity, ambient configuration, URLs, and TLS overrides fail closed. Descriptions replace the password with `REDACTED`; results cannot contain a URL, message, stack, token, backend secret, or raw query text.

If credentials are unavailable, PD.6C requires these operator-local values and must stop before connection: host `127.0.0.1`, port `55432`, database `afex_a25_pd6`, user `afex_a25_pd6_runner`, and the manually chosen password. The password must be supplied through a local ignored secret mechanism and never retained.

## Evidence models

Type evidence records actual pg 8.22.0 behavior rather than assuming it. Candidate classes are number for int4, string for int8/numeric, boolean, UUID string, parsed JSON values, Buffer, array, null, and Date for both timestamp types. Global type parsers are never changed.

For lock evidence, `withLockControl` creates a separately labelled public `pg.Client` using the same validated runner configuration. It begins a transaction and executes only the fixed no-op update on `pd6_evidence.lock_target`. The max-one adapter borrower begins independently, applies transaction-local lock timeout, attempts the same fixed update, observes `55P03`, settles, rolls back once, and returns to I. The control facility bounds connect at 3000 ms, `BEGIN` at 750 ms, lock acquisition at 1000 ms, its callback critical section at 1500 ms, rollback cleanup at 750 ms, and `end()` at 750 ms. Their 7750 ms sequential maximum leaves 750 ms inside the frozen 8500 ms total control budget.

Callback expiry terminalizes callback authority before cleanup. The facility does not wait for a non-settling callback, attempts exactly one rollback if its transaction began, and attempts `end()` exactly once even when rollback rejects or expires. Rollback and close cannot introduce an unbounded cleanup phase. A late callback result or rejection is observed and discarded; it cannot restore success, reopen the connection, mutate the bounded failure, or trigger a second cleanup. Raw callback values and errors are not retained. Cleanup failures use the existing bounded PD.5 classifications, with no new failure code, SQLSTATE, retry, borrower-pool effect, or private pg cancellation surface. It is not a borrower pool and cannot accept SQL.

Permission-denial operations are fixed and executed only within explicitly controlled PD.6C flows. Public/evidence schema CREATE and prohibited fixture DML must fail. A success is a blocking security defect, not evidence to clean up casually. PostgreSQL permission denial normally reports `42501`, but that value is outside the frozen PD.5 SQLSTATE allowlist. PD.6 retains the closed `PG_QUERY_FAILED` classification and a null SQLSTATE rather than silently widening the contract; retaining `42501` requires a separately reviewed PD.4B amendment.

Destruction evidence compares JavaScript client object identity only inside test bookkeeping: explicitly destroy the owned client via the adapter release decision, acquire again, and require a different object. PID is neither retained nor treated as borrower identity.

Ambiguous COMMIT is deferred. Container-stop or network timing cannot deterministically prove whether COMMIT took effect and could disturb unrelated state. PD.5 unit evidence remains the authority until a controlled proxy or provider test is separately reviewed. Real pool errors and protocol corruption are likewise deferred when no public deterministic trigger exists.

Timestamp decoding records two separate facts: the observed JavaScript class and the semantic timezone interpretation. Actual pg behavior must be measured in PD.6C. In particular, Node process timezone can affect interpretation of `timestamp without time zone`; no UTC or Production behavior is assumed. No global type parser is changed.

## Result integrity

`createBoundedResult` explicitly validates every field against the same enums, nullability, types, and numeric bounds as the closed JSON schema; tests compare the runtime and schema vocabularies directly. SQLSTATE is allowlisted, retry must be the boolean `false`, rollback attempts are integers from zero through one, and raw errors are discarded after bounded classification. Canonical digest input is sorted by logical scenario ID and excludes wall-clock timestamps.

## Canonical Digest Version Policy

`driver_version` and `postgres_version` are retained canonical fields and participate in the canonical evidence digest exactly as represented in each bounded result. `driver_version` must reflect the exact pinned driver authority, `pg@8.22.0`. Before real PostgreSQL observation, `postgres_version` may be null only where the schema permits and the scenario has not yet executed. During executed PD.6C Direct PostgreSQL evidence, `postgres_version` must contain the observed bounded PostgreSQL version value required by the result contract.

Version values are not normalized away from digest authority. A driver or PostgreSQL version change is expected and intended to change the digest; cross-version digest equality is not claimed. Wall-clock timestamps, elapsed durations, passwords, URLs, raw errors, backend PIDs, random identifiers, and transient JavaScript object identity remain excluded from canonical digest authority.

The 9000 ms overall timer starts before the first post-checkout borrower operation. Application timing starts at query/COMMIT dispatch; settlement and rollback budgets begin only when their respective phases begin. The worst sequential application-deadline path is 6500 ms, leaving 2500 ms for bounded orchestration overhead.

PD.6B proves implementation safety only. Its cleanup proof uses fake clients and an injected scheduler without wall-clock sleeps. It does not claim a PostgreSQL checkout, query, timeout, decoding result, transaction status, release, or provider behavior; no database evidence exists yet.
