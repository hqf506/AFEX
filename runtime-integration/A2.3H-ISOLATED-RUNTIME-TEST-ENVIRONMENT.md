# A2.3H Isolated Runtime Test Environment

Status: DESIGN ONLY — NO ENVIRONMENT CREATED

## Isolation boundary

Use a separate disposable test database or dedicated test schema when the provider permits. It must contain no Production business data and must not invoke P2D.20, application routes, legacy order creation, or any business table write.

## Future identities and objects

- One restricted dedicated test LOGIN with a generated secret delivered outside Git.
- One dedicated `NOLOGIN`, `NOINHERIT` test execution role.
- SET-only membership with ADMIN=false and INHERIT=false.
- One harmless catalog-only or constant-return test function owned by a dedicated test owner.
- No access to customer, tenant, order, payment, inventory, payload, command, context, audit, or outbox tables.
- Optional dedicated test schema with no PUBLIC/browser/service-role access.

Object names, ownership, grants, membership, search path, and cleanup are frozen only in the future reviewed SQL package. Production role names must not be targeted by arbitrary test input.

## Runtime harness boundary

The future harness uses synthetic correlation IDs, bounded disposable connections, a hard maximum pool, explicit transaction state, deterministic timeouts, and no application route. It records identity/catalog facts only. It exposes no generic SQL endpoint and accepts no arbitrary role or statement from the operator.

## Credentials

Use a short-lived restricted test credential stored in an approved isolated secret store. Never place it in Git, command output, evidence, screenshots, URLs, Preview, client bundles, or environment dumps. Rotation and revocation are part of the tests.

## Evidence and audit

Record test/run IDs, timestamps, client instance ID, pseudonymous connection ID, backend PID, transaction identifier where available, role states, reset checks, SQLSTATE, duration, and pass/fail. Record object/role creation and cleanup attestations. Do not record SQL text containing secrets or complete connection parameters.

## Cleanup

Stop new work, drain/cancel bounded operations, close/destroy all connections, revoke membership and LOGIN access, drop only reviewed test objects, attest absence of sessions/locks/grants/objects, revoke the credential, hash evidence, and retain the cleanup result. Cleanup failure blocks architecture approval.

## Stop conditions

Stop on any Production endpoint ambiguity, business-table access, unexpected privilege, identity mismatch, role/GUC/search-path contamination, uncontrolled connection growth, secret exposure, uncertain cleanup, or provider behavior outside the approved test contract.
