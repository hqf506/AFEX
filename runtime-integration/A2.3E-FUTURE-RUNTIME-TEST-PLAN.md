# A2.3E Future Runtime Test Plan

Status: DESIGN ONLY — NOT AUTHORIZED FOR EXECUTION

## Preconditions

Use an isolated approved environment, synthetic identities, a dedicated test login, reviewed non-production credentials, provider approval where required, bounded concurrency, complete evidence capture, and an explicit teardown review. No executable SQL or implementation is included here.

## Test matrix

| Test | Required observation | Fail-closed result |
|---|---|---|
| Identity before activation | `session_user` and `current_user` equal the login identity | Stop if unexpected role is active |
| Identity during activation | `current_user` becomes only the approved runtime role | Stop if activation fails or broadens |
| Identity after transaction | Role returns to login identity | Reject topology on persistence |
| Backend PID reuse | Record pseudonymous PID continuity across bounded calls | Never infer cleanup from PID alone |
| Sequential contamination | Second client receives no first-client role/session state | Reject on contamination |
| Concurrent contamination | Parallel clients retain isolated identity/state | Reject on cross-client state |
| Forced-exception rollback | Atomic work and role state roll back | Reject on residue |
| Abrupt disconnect | Server rolls back before backend reuse | Reject if outcome/state unsafe |
| Statement timeout | Timeout rolls back and sanitizes connection | Reject on residue |
| Cancellation | Cancellation yields safe rollback/recovery evidence | Reject if ambiguous and unrecoverable |
| Unknown commit outcome | Idempotent retry classifies without duplicate work | Reject if duplicates or unsafe ambiguity |
| Advisory lock | Transaction lock scopes and releases as frozen | Reject if unsupported or persistent |
| Prepared statement | Behavior matches selected pooling mode | Disable unsupported mode or reject topology |
| Pool exhaustion | Requests fail boundedly without credential/state leakage | Reject if cascading or unobservable |
| Credential rotation | New credential activates; old is revoked without Preview exposure | Reject unsafe lifecycle |
| Expired credential | Fails closed with no fallback identity | Reject broad fallback |
| Revoked membership | Activation fails closed immediately | Reject cached/bypassed authority |
| Database failover | Connections recover without state contamination or duplicate command | Reject unsafe recovery |

## Evidence per test

Record run ID, environment, provider mode, UTC start/end, sanitized configuration identifiers, expected state, observed state, exit/result class, bounded timing, server correlation reference, stderr/stdout paths, reviewer, and hash manifest. Do not record credentials, complete URLs, raw business payloads, customer data, or unmasked provider logs.

## Review

Tests are independently approved, executed, and reviewed. A provider claim does not pass a runtime-test gate. Failed and indeterminate evidence is retained safely and maps to the applicable G1–G12 gate. No test automatically selects an architecture outcome.
