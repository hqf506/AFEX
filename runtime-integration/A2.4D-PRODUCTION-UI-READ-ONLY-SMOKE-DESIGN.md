# A2.4D Production UI Read-Only Smoke Design

Status: DESIGN ONLY; NOT AUTHORIZED OR EXECUTED

## Secret boundary

The operator supplies `AFEX_TEST_USERNAME`, `AFEX_TEST_PASSWORD`, and `AFEX_TEST_PIN` only through temporary local environment variables. The procedure must never echo, interpolate into command lines, persist, screenshot, log, or copy their values. Database credentials and Supabase direct access are prohibited.

## Authorized scope after separate human approval

1. Open the allowlisted public AFEX Production URL `https://www.smart-afex.com/admin/dashboard`.
2. Authenticate only with the dedicated temporary UI account.
3. Confirm login success/failure, authenticated-route reachability, and visible dashboard load.
4. Navigate read-only through existing dashboard and POS entry surfaces only as explicitly approved; stop before any create, submit, save, update, delete, notification, or external-contact action.
5. Capture browser-console error counts, failed network requests, and route timing summary without response bodies containing business data.
6. Record only a one-way masked account identifier, never username, email, phone, PIN, token, cookie, or session value.
7. Redact screenshots to exclude credentials, customer/order/payment data, tenant identifiers, staff details, and business-sensitive dashboard values.
8. Store evidence only beneath a proven Git-ignored local directory, then clear the temporary environment variables.

## Prohibited actions

No order/customer/user creation; no checkout submission; no settings, branch, permission, integration, tenant, inventory, or notification change; no real customer contact; no SQL/database credentials; no Core V2 flag or route activation.

## Evidence schema

- Timestamp and approved operator/reviewer reference.
- `login_result`: `PASS`, `FAIL`, or `BLOCKED`.
- Reachable route names only.
- Dashboard visible-load result.
- Console-error summary with sanitized error classes.
- Failed-request method/path/status only, with query secrets removed.
- Navigation and route timing summary.
- Masked account digest/reference.
- Screenshot inventory and redaction attestation.
- Explicit attestation that no write action was submitted.

This phase does not execute the smoke test. Separate UI smoke authorization is required.
