# A2.3 Role Membership Contract

Status: normative design; no role or membership has been created

## Dedicated LOGIN contract

Conceptual name: `afex_core_app_login`. Final name requires organizational approval.

| Property | Required state |
|---|---|
| LOGIN | True |
| INHERIT | False |
| SUPERUSER / BYPASSRLS | False / false |
| CREATEDB / CREATEROLE / REPLICATION | False / false / false |
| Ownership | Owns no database, schema, relation, sequence, function, policy, extension, or publication object |
| Direct ACLs | No direct schema/table/column/sequence/function privileges |
| Connection limit | Positive finite value derived from approved global capacity; not invented here |
| Validity | Finite `VALID UNTIL`, aligned with credential rotation; never indefinite without explicit exception |
| Role configuration | Exact reviewed baseline only; no mutable request-supplied search path or authority GUC |
| Credential | Random provider-supported secret, server-only, separately stored per environment |

## Allowed graph

The only application edge is:

`afex_core_app_login` (member) → `afex_core_runtime` (parent/granted role)

Required membership options on PostgreSQL 17.6:

- `SET OPTION TRUE`
- `INHERIT OPTION FALSE`
- `ADMIN OPTION FALSE`

The grantor must be the separately approved role administrator with authority to create/revoke this exact edge. The application LOGIN may SET only `afex_core_runtime`; it may not grant or revoke membership.

The existing Supabase-administered `postgres` membership in `afex_core_runtime` remains untouched.

## Forbidden graph

- `afex_core_runtime` as member of any parent role.
- `anon`, `authenticated`, `authenticator`, `service_role`, browser, issuer, worker, provider, or dashboard role as member of Runtime.
- Dedicated LOGIN membership in `postgres`, service roles, owner roles, managed roles, or any role other than Runtime.
- Runtime membership in the dedicated LOGIN.
- Inherited or administrative Runtime membership.
- Membership target taken from HTTP, payload, environment free text, or caller argument.

## Grant/revoke authority

Creation and membership are one externally reviewed installation package, but failure must leave no partially usable LOGIN. Revocation order for normal shutdown is: disable trusted-client gate; drain calls; revoke/expire credential; terminate/quarantine sessions using that LOGIN; remove the exact membership; attest no reachability; retain durable commands. Emergency revocation may immediately expire/disable the LOGIN and terminate sessions before application drain.

Break-glass operators do not use the application secret and do not grant broader membership. Every break-glass action requires separate incident authorization and post-event attestation.

## Postconditions

- LOGIN cannot use P2D.20 before explicit Runtime activation.
- Runtime retains the single exact direct P2D.20 EXECUTE contract and no relation access.
- LOGIN cannot SET any other role.
- Runtime and LOGIN own nothing.
- Managed Supabase roles and the postgres edge are unchanged.
- Membership, ACL and ownership attestations fail on any additional row.
