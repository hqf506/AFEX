# A2.3G Allowed and Blocked Work

| Work item | Classification | Boundary |
|---|---|---|
| A. Documentation-only work | ALLOWED_NOW | May refine ADRs, test plans, evidence schemas, SQL specifications, and review checklists without asserting unproven behavior. |
| B. SQL design only | ALLOWED_WITHOUT_ACTIVATION | Dedicated LOGIN/membership design may be produced for review; no execution, password literal, secret, or assumption of provider support. |
| C. SQL execution | BLOCKED | Requires provider evidence, external SQL review, explicit manual-execution approval, revocation/rollback, and attestation. |
| D. Package/library ADR | ALLOWED_NOW | May compare `pg` and postgres.js on Node 24, transaction pinning, role operations, cancellation, prepared statements, serverless lifecycle, observability, and narrow API exposure. |
| E. Package installation | BLOCKED | No package or lockfile change until ADR and separate approval. |
| F. Pure adapter contracts | ALLOWED_WITHOUT_ACTIVATION | Configuration types, domain-only interfaces, state-machine declarations, mocked transports, fixtures, scanners, disabled factory, and forbidden-import rules may be separately authorized. |
| G. Connection factory implementation | BLOCKED | No credentials, pools, sockets, provider endpoint, or process-global client may be introduced yet. |
| H. Runtime transaction/role wrapper | BLOCKED | Pinning, activation, cleanup, cancellation, and advisory-lock behavior are unproven. |
| I. Production integration | BLOCKED | No P2D.20 application call, route change, dual write, fallback, or Production smoke call. |
| J. Feature-gate activation | BLOCKED | All G1–G12 evidence and release approvals must pass first. |

## LOGIN SQL design decision

`LOGIN_SQL_DESIGN_MAY_BEGIN`

Design is permitted only as a separately reviewed, forward-only specification/package. It must include exact preflight, role attributes, SET-only membership, ownership/grant boundaries, credential separation, revocation/rollback, postcondition attestation, idempotent failure behavior, and PostgreSQL 17.6 catalog compatibility. It must contain no password literal or secret and must not be executed in the design phase.

## Driver decision

`DRIVER_INSTALLATION_BLOCKED_BUT_ADR_ALLOWED`

The ADR must compare Node 24 support, transaction checkout/pinning, cancellation, prepared statements, error classification, observability, pool shutdown, connection quarantine, and whether the public module can prevent generic SQL/query exposure. No package selection may be treated as topology proof.

## Pure skeleton decision

`PURE_SKELETON_IMPLEMENTATION_MAY_BEGIN`

This is an eligibility decision, not implementation authorization. A separate phase may implement only credential-free, network-free, hard-disabled declarations and mocks. It must not import a PostgreSQL driver, create a pool, read a database credential, call P2D.20, modify a route, activate a flag, or alter legacy behavior.

## Work that remains prohibited

No SQL execution, database/provider contact, package installation, environment change, LOGIN creation, membership change, runtime connection, generic query API, service-role fallback, dual write, post-send legacy fallback, route activation, or feature enablement.
