# A2.5.PD.5 Real Driver Adapter Design

## Scope and authority

This adapter implements the frozen PD.4B contract against the public `pg@8.22.0` surface. It is an internal, dependency-injected boundary for no-network testing; it is not wired into the application and contains no connection configuration or executable SQL. The package remains private ESM with `@types/pg@8.20.4`.

## Architecture

| Unit | Responsibility |
|---|---|
| `RealDriverAdapter` | Pool checkout, mandatory pool observation, and creation of one-owner leases |
| `ClientLease` | Borrower identity, query lifecycle, transaction orchestration, owned-client events, sanitation, and exactly-once release |
| `RollbackCoordinator` | Closed rollback state machine with at most one attempt after ordinary settlement |
| `PoolErrorObserver` | Bounded idle/pool error evidence without poisoning unrelated borrowers |
| `observeTransactionStatus` | Narrow guarded adaptation of documented runtime status |
| `verifySanitation` / `decideRelease` | Pure sanitation and terminal-action gates |
| error-map module | Closed 23-code vocabulary, allowlisted SQLSTATE classification, precedence, bounded evidence |
| timeout module | Pure timeout taxonomy, plan validation, deterministic injected scheduler/deadline |

## Public API usage and type adaptation

The runtime boundary uses only `pool.connect()`, `pool.on('error')`, `PoolClient.query()`, client `error`/`end` EventEmitter behavior, `client.release()`, `client.release(true)`, and documented `client.getTransactionStatus()`. The test imports the public `Pool` constructor for surface presence but never instantiates it.

`@types/pg@8.20.4` omits `getTransactionStatus()`. Because this implementation is JavaScript, the narrow adaptation is a local runtime guard in `observeTransactionStatus`; no ambient declaration, package patch, or private field is needed. Missing, throwing, null, undefined, invalid, or expected-state contradiction maps to `UNKNOWN`. No `_txStatus`, backend PID/key, parser, socket, or protocol internals are accessed.

## Ownership, events, and query lifecycle

One nonempty local borrower token owns each lease. Every operation checks it. A centralized gate admits exactly one of query, COMMIT, rollback, sanitation, or release; overlap maps to the frozen `PG_RELEASE_STATE_INVALID`. Mismatch records `PG_IDENTITY_MISMATCH`; released/destroyed leases reject further use. Release terminalizes ownership before detaching listeners and invoking exactly one `release()` or `release(true)` call. If normal release throws it retains `PG_RELEASE_STATE_INVALID`; if destructive release throws it retains `PG_CLIENT_DESTROY_REQUIRED`. In either case the lease remains terminal and the external call is never retried.

Client `error` and `end` listeners mark an owned client unsafe. SQLSTATE `08P01` is bounded to protocol error; end is bounded to socket error; other client errors are bounded to client error. The pool listener retains only code, stage, allowlisted SQLSTATE, transaction-status classification, and the constant no-retry decision. Raw messages and error objects are never retained.

Borrower queries require a closed descriptor containing `operationId`, optional values, and optional timeout classification. Raw `text`, `name`, `sessionMutation`, and unknown properties are rejected. Only the constructor-injected trusted executor can translate the identifier into a future reviewed unnamed query, making arbitrary borrower SQL and session mutation structurally unavailable. Lifecycle is `NOT_STARTED`, `PENDING`, `ORDINARY_SUCCESS`, `ORDINARY_ERROR`, or `UNKNOWN`. A positive driver `query_timeout` is classified locally as unsafe rather than dispatched. No query text enters borrower evidence.

## Timeouts and transaction outcomes

The timeout taxonomy contains checkout, connection establishment, application deadline, driver query, server statement, server lock, idle-in-transaction, cancellation settlement, rollback, client destruction, and overall operation classes. Plan validation enforces bounded positive budgets and the frozen ordering constraints. The injected scheduler is monotonic, stable for equal deadlines, cancellable, and uses no wall clock. Query and COMMIT expose deterministic deadline transitions. An application or overall deadline during `COMMIT_PENDING` immediately makes the outcome `AMBIGUOUS`, wakes the awaiting adapter call with `PG_COMMIT_OUTCOME_UNKNOWN`, and requires destruction. Handlers remain attached to the underlying promise solely to consume late settlement; late resolution or rejection cannot restore outcome authority, trigger rollback, or enable retry.

Transaction status maps `I` to `IDLE`, `T` to `IN_TRANSACTION`, `E` to `FAILED_TRANSACTION`, and every other result to `UNKNOWN`. Unknown never authorizes normal release.

Rollback states are `NOT_REQUIRED`, `REQUIRED`, `ATTEMPTED`, `SUCCEEDED`, `FAILED`, `TIMED_OUT`, and `SKIPPED_UNSETTLED`. Internally, command outcome (`NOT_ATTEMPTED`, `SUCCEEDED`, `FAILED`, `TIMED_OUT`, or `SKIPPED`) and the separately observed post-command transaction status are retained as distinct dimensions. A rollback can begin only after ordinary settlement or a known non-commit. Command rejection maps to `PG_ROLLBACK_FAILED`; timeout maps to `PG_ROLLBACK_TIMEOUT`; a successful command followed by `UNKNOWN` maps to `PG_TRANSACTION_STATUS_UNKNOWN`. Successful command plus `IDLE` permits later sanitation, while `T` or `E` is an ended-non-idle rollback mapped to `PG_ROLLBACK_FAILED`. Every unsafe outcome destroys, never retries, and never starts a second rollback.

COMMIT outcomes are `NOT_ATTEMPTED`, `KNOWN_COMMITTED`, `KNOWN_NOT_COMMITTED`, and `AMBIGUOUS`. Promise rejection alone is insufficient for known non-commit. Unsettled work, unsafe events, or unknown/idle-after-rejection evidence is ambiguous: destroy, no rollback-as-proof, and no retry.

## Release, failure mapping, and sanitation

`NORMAL_RELEASE` requires ownership, ordinary settled work, no active operation, `IDLE`, a known outcome, satisfied rollback state, no unsafe event, sanitation pass, identity match, no outstanding timeout, and no previous release. It calls `client.release()`. Any acquired client failing a condition gets `DESTROY_RELEASE` and `client.release(true)`; an unacquired state gets `NO_RELEASE`. Ownership becomes irreversibly terminal before either external call, so an exception cannot create a listener-free reusable lease.

Failure precedence, strongest first, is: commit ambiguity; connection/socket/protocol/client uncertainty; settlement/status uncertainty; rollback failure/timeout; identity/sanitation/release/destruction safety; pool acquisition/event failure; ordinary query/timeout/lock/commit/cancel-request failure. SQLSTATE is secondary and limited to `57014`, `55P03`, `40001`, `40P01`, `25P02`, `08000`, `08001`, `08003`, `08004`, `08006`, `08007`, and `08P01`. Serialization and deadlock remain non-retryable.

Sanitation is verification, not cleanup: owned transaction complete, idle, no pending work, identity intact, no unsafe event, no unresolved timeout, and no forbidden session mutation. There is no `RESET ALL`, `DISCARD ALL`, or `RESET ROLE` behavior.

The sanitation gate re-observes the public transaction status instead of trusting a cached post-rollback value. An ordinary query rejection that settles with unavailable or invalid transaction status is elevated to `PG_TRANSACTION_STATUS_UNKNOWN`; the originating SQLSTATE classification remains secondary bounded evidence and cannot authorize reuse.

## Limitations and next evidence gate

These tests prove adapter logic only. They do not prove network, PostgreSQL, transaction-local SQL, ReadyForQuery timing, pool replacement, Supavisor, Vercel, or provider behavior. Explicit pg cancellation remains zero. The next gate after independent PD.5 review is a separately authorized real-database evidence phase; this artifact does not authorize it.
