## Enforcement model

The scanner uses the existing deterministic module graph for relative paths, `@/` aliases, export-from, CommonJS `require`, literal dynamic imports, static template imports, barrel chains, and cycles. Adapter diagnostics identify the root, chain, source, exact source coordinates, and import kind. Forbidden external package specifiers are evaluated only as import specifiers, not comments or ordinary strings. Identical findings are deduplicated while real distinct roots/origins remain separate.

Environment enforcement recognizes `process.env`, `import.meta.env`, bracket forms, destructuring/aliases, and transitively reachable wrappers. Generic surface enforcement tracks provenance through variables, multi-hop/export/destructured aliases, function returns, object spreads, literal/enum/readonly/concatenated computed keys, mapped types, concrete conditional types, declaration merging, and statically reachable inherited declarations. Diagnostics identify origin, coordinate-bearing provenance steps, and final exposure/use. Fixture assertions verify structured locations and required diagnostic fields.

P2D.20 enforcement covers direct/property/computed calls, imported/local/destructured aliases, RPC literal calls, and transitively reachable wrappers. Role-target enforcement normalizes case, underscores, and hyphens for the approved forbidden vocabulary while leaving lifecycle strings inert.

The fake source has an exact importer allowlist containing only the contract runner and adapter type-test script. Any other statically resolvable import path to the fake fails, including production barrels and arbitrary server scripts.
