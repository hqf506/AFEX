## Transport contract

PASS. `TrustedAcquisitionTransport` has exactly one operation, `acquire`. Its input and output are direct aliases of `AuthorizationContextAcquisitionInput` and `P2D20RawAcquisitionRow`. The eight frozen fields are preserved. No callback, credential, role target, function-name parameter, connection, transaction callback, generic database method, index signature, `any`, or generic escape exists in the actual interface.

TypeScript structural casts can manufacture another object implementing the interface, but they cannot make the factory's frozen lexical transport operational. This language-level limitation must not be treated as runtime provenance; the future authority sealer remains required.

## Disabled factory

PASS. The factory accepts no arguments and always returns a frozen singleton. Its `acquire` closure always throws a new error with code `CORE_V2_ADAPTER_DISABLED`. Object spreading only copies the failing closure. The object cannot be mutated or subclassed, dependency injection and callbacks are absent, and monkey-patching the exported error prototype cannot replace the lexical `acquire` closure. The message and code contain no credential, query, payload, or internal state.

## Lifecycle

PASS. The 14 values are frozen declarations only. They do not execute transitions and do not overlap the installed command statuses. Authority is not claimed until both before- and after-activation identity states. Rollback, cleanup, quarantine, and fail-closed states remain explicit. Unknown-outcome reconciliation is not implemented or falsely claimed.

## Test fake

The fake is absent from production barrels and records only count and disposition. It cannot create sealed database authorization provenance because it returns only the already-designated raw-row boundary. Two limitations require correction: direct-import reachability is not scanner-enforced, and shallow copying permits a caller to mutate a predetermined row after construction but before acquisition.

## Export boundary

PASS for current source. `lib/core-v2/index.ts` is unchanged. The adapter barrel exports only the frozen input/raw-result aliases, one-method interface, disabled code/error, and factory. It excludes lifecycle declarations, the fake, credential topology, authority sealer, normalizers, drivers, Pool/Client types, and concrete transport internals.

## Scanner findings

All rule IDs are stable and each has one direct positive fixture with nonzero status and source location. Existing import parsing handles relative/path-alias static imports, `require`, literal dynamic imports, static template imports, comments, and BOMs generally. The new fixtures do not include corresponding safe cases or adversarial transitive variants.

Independent virtual-file probes returned zero findings for all of these forbidden forms:

- adapter -> local wrapper -> `pg`;
- adapter -> local environment wrapper;
- computed `['query']` method;
- exported function-valued `query` property;
- aliased P2D.20 call;
- `client.rpc('acquire_atomic_order_command_v1')`;
- computed `['roleTarget']` field;
- adapter index -> intermediate barrel -> test fake;
- direct test-fake import from a non-route server module.

Therefore “fixture-covered” proves only that one selected syntax reaches each rule; it does not prove the declared boundary.

## Adversarial findings

Declaration merging, computed names, symbol names, inherited members, aliases, indirect wrappers, intermediate barrels, and nonliteral dynamic imports are not all statically provable with the present scanner. `any` and explicit casts are also not generally decidable as security boundaries. The next correction must define a conservative AST/import-closure policy and explicitly document irreducible cases rather than claiming comprehensive enforcement.

## Frozen-contract compatibility

No conflict was found with A1 authority provenance, raw acquisition invariants, idempotency, replay, safe errors, outbox rules, or with A2.1/A2.2 architecture. No concrete lifecycle behavior contradicts A2.3. The hard-disabled status correctly preserves all A2.3H provider blockers.

## Driver ADR

The boundary report's statement that scanner rules enforce the no-activation invariants is too broad: the current live tree is clean, but multiple prohibited future forms evade the scanner. “Each rule has an isolated fixture” is accurate but insufficient without safe/adversarial coverage.
