# A2.3G Final Runtime Connection Architecture Gate Review

Status: ARCHITECTURE NOT YET APPROVED FOR RUNTIME ACTIVATION

## Executive verdict

The committed A2 baseline and accepted dashboard evidence materially narrow the candidate topology but do not prove transaction-pool safety. No G1–G12 gate is fully proven end to end. G6–G9 and G12 are partially proven; G1–G4 await provider confirmation; G5, G10, and G11 require isolated runtime tests in addition to provider facts.

The preferred candidate remains a dedicated `afex_core_app_login` using the Supabase transaction pooler, with SET-only membership in `afex_core_runtime`. This remains conditional. `service_role`/PostgREST, browser credentials, dual write, legacy fallback after an uncertain send, and unproven session pooling remain rejected.

## Established facts

- `afex_core_runtime` is isolated, `NOLOGIN`, `NOINHERIT`, owns no objects, and has only the approved acquisition EXECUTE grant.
- P2D.20 is installed but not wired into application runtime.
- Direct, transaction-pool, and session-pool connection methods are dashboard-visible.
- Transaction pool size is 15 and maximum client connections is 200; current utilization and safe AFEX allocation are unknown.
- Next.js 16.2.10 and Vercel Node 24.x are identified; no PostgreSQL client package is installed.
- No preferred region or max-duration source declaration exists, and effective Vercel function topology remains incomplete.
- The verified source baseline is clean and synchronized with `origin/master` at `0f6ae374984b9f44d1097531c3a07b571e1c686f`.
