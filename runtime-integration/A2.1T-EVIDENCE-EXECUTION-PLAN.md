# A2.1T Runtime Privilege Closure Evidence Execution Plan

## Purpose and boundary

This package acquires the catalog evidence required to design Runtime Privilege Closure. It is discovery-only. It neither selects a target LOGIN role nor changes a role, privilege, object, policy, application path, or database state.

The SQL runs in an explicit read-only transaction and ends with `ROLLBACK`. The runner must not be used with a target-role parameter. A target mode requires separate approval and a separately reviewed artifact.

## Prerequisites

- Repository artifacts have completed external review.
- Windows PowerShell can parse the runner without errors.
- PostgreSQL 18 `psql.exe` exists at the pinned runner path.
- `SUPABASE_DB_URL` is defined only in the operator process and contains an approved TLS mode: `require`, `verify-ca`, or `verify-full`.
- The connected database identity can read the required PostgreSQL catalogs without exposing password hashes.
- No other A2.1T run is assumed reusable after a failure.

## Frozen artifacts and expected hashes

The executable runner pins the exact SHA-256 of `A2.1T-RUNTIME-PRIVILEGE-CLOSURE-EVIDENCE.sql`. Before execution, the operator must compare the SQL and runner hashes with the externally reviewed values in the review response. Any mismatch is a STOP condition.

## Manual execution command

From the repository root, after setting `SUPABASE_DB_URL` in the current process:

```powershell
& .\database-reconciliation\core-v2\P2D\A2.1T-RUN-EVIDENCE-DIAGNOSTIC.ps1
```

No command-line database URL or password is permitted.

## Evidence directory

Each run creates a new local directory:

`database-reconciliation/core-v2/P2D/evidence/A2.1T-<UTC timestamp>/`

Expected files:

- `010-a21t-evidence.stdout.txt`
- `010-a21t-evidence.stderr.txt`
- `step-results.txt`

Evidence is local operational output. It must remain untracked until it has been reviewed for metadata sensitivity and an explicit evidence-retention decision has been made.

## Success criteria

- SQL hash matches the runner pin.
- Process completes within the configured timeout.
- `psql` exit code is zero.
- stderr contains no PostgreSQL `ERROR` or `FATAL` diagnostic.
- stdout contains exactly the reviewed completion marker.
- Summary records `result=PASS`.
- Credential environment state and the temporary pgpass file are cleaned in `finally`.

The evidence sufficiency classification may still be blocking. A successful diagnostic means the evidence acquisition completed; it does not approve privilege closure.

## Failure criteria and STOP conditions

- Missing or malformed `SUPABASE_DB_URL`.
- SQL hash mismatch.
- Unsupported catalog semantics or missing Core V2 identities.
- Ambiguous or duplicate Core V2 function identity.
- Timeout.
- Nonzero native exit code.
- PostgreSQL `ERROR` or `FATAL` in stderr.
- Missing completion marker.
- Credential cleanup failure.

On any failure, stop. Preserve the evidence directory. Do not automatically rerun, edit the diagnostic, choose a target LOGIN, or create closure SQL.

## Evidence return for review

Return the complete, unmodified contents of all three evidence files, their full paths, byte counts, and SHA-256 hashes. Also provide separately controlled external evidence for Supabase exposed schemas, pool mode, reset behavior, and connection-return sanitation. Do not return the database URL or credentials.

## Review sequence

1. Validate artifact hashes and runner syntax.
2. Run once manually under the approved read-only identity.
3. Preserve stdout, stderr, and summary.
4. Review candidate reconciliation and the closed-enum classification.
5. Reconcile database evidence with external pooling and PostgREST configuration.
6. Only then decide whether A2.1 privilege-closure design can resume.
