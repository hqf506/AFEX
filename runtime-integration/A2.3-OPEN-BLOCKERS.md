# A2.3 Open Blockers

Status: Critical blockers prevent implementation and Production activation

## Critical

| Blocker | Missing proof | Resolution owner |
|---|---|---|
| Dedicated LOGIN | Final name, authority, finite limit, validity, credential lifecycle | Database/Security |
| Membership | PostgreSQL 17.6 SET-only edge and authorized grantor/revoker | Database/Security |
| Supavisor topology | Transaction pinning, role support, reset, cancellation, prepared behavior | Supabase/Platform |
| Connection cleanup | Reuse tests after every success/error/abort condition | Application/Platform/Security |
| Vercel runtime topology | Node version, region, TCP support, concurrency, duration, freeze/thaw | Platform |
| Capacity | Compute limits, current use, reserved capacity, POS/retry load | Database/Operations |
| Secret lifecycle | Environment separation, custody, rotation, revocation, audit | Security/Platform |
| PUBLIC closure | Exact consumer and managed-object dispositions from A2.1T | Database/Application owners |
| Role activation attestation | session/current identity proofs and post-return sanitation | Database/Application |

## High

- Driver selection and version-specific cancellation/TLS behavior.
- Numeric timeout and performance budget reconciliation with A1.
- Direct connection IPv4/IPv6 and failover behavior.
- Separate command-service cost, location, signing and availability if fallback is needed.
- Unknown external cron/webhook/Edge/worker consumers.
- Preview/development isolation and safe disabled behavior.

## Contract reconciliation

No design conflict with A1 or A2.2 was found. The unresolved topology affects performance and operational contracts, so numeric choices remain blocked rather than silently amended. Authorization, idempotency, replay, payload, response, error, security, disabled-by-default, no-dual-write and no-fallback invariants remain unchanged.

## Stop conditions

Stop if any identity differs, service_role is proposed, role target becomes dynamic, transaction pinning is unproven, cleanup cannot discard a connection, capacity lacks a conservative bound, secret enters browser/repository/logs, exact P2D.20 contract drifts, or any design proposes a new key/fallback after unknown acceptance.

## Readiness

Architecture review may proceed. Dependency installation, SQL generation, role creation, trusted-client skeleton, database connection, P2D.20 wiring and Production enablement remain blocked.
