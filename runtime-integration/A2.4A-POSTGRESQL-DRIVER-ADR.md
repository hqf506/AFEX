# A2.4A PostgreSQL Driver ADR

Status: `PG_SELECTED` — selection does not authorize installation or use.

## Decision

The future reviewed transport will use node-postgres (`pg`). Vercel's accepted guidance explicitly demonstrates and recommends a process-global `pg` Pool, bounded above one, with short idle timeout and `attachDatabasePool`. This decision preserves every A2.3 gate: no package, client, Pool, credential, connection, role activation, or acquisition call is authorized now.

## Comparison

| Concern | `pg` | postgres.js |
| --- | --- | --- |
| Explicit transaction checkout | Mature `PoolClient` checkout model; backend pinning still requires isolated proof | Transaction callback model; pooler behavior still requires proof |
| Cancellation/timeouts/SQLSTATE | Mature error fields and cancellation mechanisms; exact unknown-outcome policy needs tests | Strong timeout primitives; exact cancellation and SQLSTATE mapping needs tests |
| Prepared statements | Named persistent statements can be avoided; unnamed parameterized calls fit the pooler constraint | Preparation can be disabled, but defaults and lifecycle require review |
| Vercel lifecycle | Directly matches accepted `Pool` and `attachDatabasePool` guidance | No equally direct provider evidence in the reviewed record |
| Node 24/TLS/observability | Candidate is mature and broadly typed; exact Node 24, TLS, telemetry, and bundle behavior require isolated proof | Mature and typed; same proof is missing, with less provider-specific evidence |
| Narrow wrapper | Supports an internal checked-out-client implementation hidden behind one domain operation | Also feasible, but tagged-template ergonomics increase accidental generic-SQL surface risk |

`pg` wins on provider evidence and narrow-wrapper feasibility. Neither driver is approved for Production until connection pinning, role activation, cleanup, cancellation, advisory-lock, capacity, TLS, and Node 24 tests pass.

## Future package contract

- Future dependency: `pg`, only after a separate package/security approval.
- Future development dependency: `@types/pg` only if the selected `pg` release does not supply sufficient types.
- Future dependency: `@vercel/functions`, only after lifecycle API and permission review.
- Select current maintained versions at authorization time; do not freeze an unverified version here.
- Review lockfile transitive changes, install scripts, licenses, advisories, Node 24 support, bundle impact, network permissions, TLS defaults, prepared-statement defaults, and cancellation semantics.
- Package installation remains blocked by unresolved Supabase and isolated-runtime gates.
