# A2.1T Evidence Schema and Interpretation

## Interpretation rule

Every section is catalog evidence, not authorization to change Production. Empty output can be meaningful, but a missing section, SQL error, timeout, inconsistent candidate count, or absent completion marker is a diagnostic failure. Function source is never emitted; only bounded indicators are reported.

## Section schema

| Section | Evidence | Interpretation boundary |
|---|---|---|
| 010 | Database identity, server/encoding/read-only state, catalog feature support, exact Core V2 identity checks | Unsupported PostgreSQL membership-option catalogs or non-exact function identity stops the run |
| 020 | Exact Core V2 role attributes and role settings | No password material is queried |
| 030 | Complete LOGIN role inventory and direct/SET reachability to Runtime | Discovery does not nominate an application LOGIN |
| 040 | Relevant direct membership edges with grantor and option flags | Direction is parent role to member role; unknown option semantics are not tolerated |
| 050 | Effective `SET ROLE` reachability | This is capability evidence, not proof that a pool performs a role transition |
| 060 | Exact ACL entries for the acquisition entrypoint and canonicalizer | Null ACL rows and PUBLIC are kept distinct |
| 070 | Every non-system function with PUBLIC-derived Runtime execution | Practical reachability additionally requires schema `USAGE`; classification is not name-based |
| 080 | PUBLIC-executable SECURITY DEFINER functions, owner power, search path, and bounded dynamic-SQL indicators | Source/dependency analysis is incomplete by design and remains fail-closed |
| 090 | Catalog-proven trigger consumers | Only non-internal triggers are emitted |
| 100 | Catalog-proven policy consumers | Absence does not prove absence of runtime callers |
| 110 | Recorded view, rule, default/generated, constraint, and function dependencies | PostgreSQL does not record all PL/pgSQL or dynamic-SQL call edges |
| 120 | Extension-owned function inventory | Managed evidence only; no modification recommendation |
| 130 | Schema effective, direct Runtime, and PUBLIC privilege sources | Effective privilege and direct ACL are separate facts |
| 140 | Effective table/view/materialized-view/foreign-table privileges and practical reachability | Managed classification and schema reachability remain explicit |
| 150 | Effective sequence privileges | Direct ACL text is evidence; no privilege is inferred from object names |
| 160 | Normalized default privileges | Current ACL causality cannot be reconstructed from defaults alone |
| 170 | Database-side PostgREST-relevant role/function exposure and overload counts | Dashboard exposed-schema configuration is external evidence |
| 180 | Objects owned by managed Supabase roles | Evidence only; managed ownership is not a closure target |
| 190 | `pg_stat_statements` relation privilege and schema reachability | PUBLIC `SELECT` without schema `USAGE` is catalog exposure but not practical reachability |
| 200 | Pool-related roles and safe session settings | Pool mode, reset-on-return, and deployment connection selection require external evidence |
| 250 | Candidate count reconciliation and normalized candidate names | All three counts must agree; multiple candidates remain ambiguous |
| 260 | Primary classification, normalized blockers, blocker count, and section map | Closed enum only; multiple blockers are retained |
| 900 | Unique completion marker | Presence is necessary but not sufficient; runner checks exit code and stderr too |

## Closed evidence classifications

- `EVIDENCE_COMPLETE_FOR_CLOSURE_DESIGN`: database evidence is internally complete and no enumerated blocker remains.
- `LOGIN_IDENTITY_MISSING`: no eligible application LOGIN is linked to Runtime.
- `LOGIN_IDENTITY_AMBIGUOUS`: more than one eligible LOGIN is linked to Runtime.
- `ROLE_GRAPH_UNSAFE`: Runtime participates in an unsafe parent or non-SET relationship.
- `PUBLIC_FUNCTION_CONSUMERS_UNPROVEN`: catalog evidence cannot prove every caller of exposed functions.
- `SECURITY_DEFINER_REACHABILITY_UNPROVEN`: privileged transitive reachability is not fully proven.
- `MANAGED_OBJECT_ACL_MODEL_UNPROVEN`: managed ownership or ACL behavior needs external authority.
- `DEFAULT_PRIVILEGE_CAUSALITY_UNPROVEN`: default ACLs cannot prove how current ACLs arose.
- `POOLING_EVIDENCE_EXTERNAL_AND_MISSING`: required pool/session evidence is outside PostgreSQL catalogs.
- `CATALOG_CAPABILITY_INSUFFICIENT`: required catalog semantics or exact Core V2 identities are unavailable; SQL stops before normal classification.
- `INCONSISTENT_EVIDENCE`: candidate counts disagree.
- `DIAGNOSTIC_FAILURE`: runner-level SQL, timeout, marker, stderr, or cleanup failure.

The primary classification is selected by fail-closed precedence. The normalized blocker list remains authoritative for all simultaneously active blockers.

## Privilege source semantics

`direct_runtime_source` means an ACL item names `afex_core_runtime`. `public_source` means the grantee OID is zero. `runtime_effective_privilege` includes all PostgreSQL-effective sources. `implicit_public_default` is true only when a function ACL is null and PostgreSQL's default function privilege applies. These fields must not be collapsed during review.

## Consumer confidence levels

- `CATALOG_PROVEN_*`: backed by PostgreSQL dependency or trigger catalogs.
- Source-text indicator: bounded boolean evidence only; it is not a parser and not a complete dependency graph.
- External/unknown: dashboard, proxy, application, dynamic SQL, or PL/pgSQL caller evidence not provable from catalogs.

## Evidence required outside this package

- Supabase/PostgREST exposed-schema configuration.
- Which LOGIN is used by the deployed Runtime.
- Supavisor/PgBouncer pool mode.
- Role/session reset behavior when a pooled connection is returned.
- Deployment connection-string selection, without disclosing its value.
- Application caller inventory for dynamic and transitive SECURITY DEFINER paths.

Until these are reconciled with the diagnostic output, privilege-closure SQL remains blocked.
