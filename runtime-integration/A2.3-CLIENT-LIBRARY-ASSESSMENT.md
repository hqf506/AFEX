# A2.3 Client Library Assessment

Status: evaluation only; no dependency selected or installed

## Repository baseline

`package.json` contains `@supabase/supabase-js` and `@supabase/ssr` only. No native PostgreSQL driver is installed. Next.js routes use the Node.js default, while only account and PDF routes explicitly pin Node. Any native driver requires a package, bundling, runtime and Vercel review.

## Comparison

| Candidate | Transactions / role / pinning | Serverless, TLS and cancellation | Fidelity and safety | Decision |
|---|---|---|---|---|
| node-postgres (`pg`) | Explicit checked-out client supports multi-statement transaction, hard-coded role activation and physical-connection pinning; pool ownership is explicit | Mature TLS/pool controls; cancellation and timeout behavior require version-specific tests; per-instance pools can storm | Native SQLSTATE fidelity and observability. Generic query API must be trapped behind an unexported narrow adapter | **Preferred library candidate** if transaction-pooler/direct topology is approved. Not installed. |

| Supabase JS/PostgREST RPC | HTTP request, no caller-owned physical transaction or connection lifecycle; cannot prove dedicated LOGIN/Runtime activation | Existing Vercel fit, TLS managed, low connection burden | Errors are PostgREST-shaped; service-role path violates approved invoker boundary; generic `rpc/from` risk | **Rejected for Core V2 trusted caller.** |
| Existing installed compatible package | None found | N/A | N/A | No candidate. |
| HTTP database gateway / separate command service | Gateway owns transaction/pool and exposes narrow endpoint | Serverless-friendly consumer; adds hop, service, signing and availability concerns | Can eliminate generic DB API from Next.js; gateway implementation must satisfy full identity proof | **Conditional fallback architecture**, not a library shortcut. |

## Selection gates

The chosen driver must support: Node.js runtime; exact TLS policy; explicit transaction; exclusive connection checkout; transaction-local role activation; integer SQLSTATE/error fidelity; statement and connection timeout; cancellation; prepared-statement controls; pool limits; close/destroy on cleanup failure; telemetry hooks; secret rotation; and a build graph that exports only the domain facade.

No library convenience may expose `query`, raw SQL, arbitrary function name, schema, table, generic transaction callback or underlying pool outside the trusted internal module.

## Required spike evidence

An isolated non-Production spike compares `pg` and postgres.js using the selected Supabase endpoint. It tests success, duplicate acquisition, SQL error, statement timeout, network cut, cancellation, transaction rollback, role restoration, connection reuse, prepared statements, cold start, pool exhaustion and secret rotation. Package selection follows evidence; it does not precede the topology decision.
