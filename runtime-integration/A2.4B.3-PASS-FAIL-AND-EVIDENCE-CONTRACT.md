# A2.4B.3 Pass/Fail and Evidence Contract

Status: SOURCE CONTRACT FROZEN; EXECUTION NOT AUTHORIZED

## Result rules

- `PASS`: every mandatory assertion and controller passed, no placeholder remains, required evidence exists, cleanup and absence attestation passed, and independent review approved.
- `FAIL`: a semantic assertion, SQLSTATE, identity, PID, lock, timeout, containment, hash, process, marker, redaction, cleanup, or privilege check failed.
- `INCOMPLETE`: any controller, evidence field, provider/operator input, cleanup, absence attestation, or independent verdict is unavailable. `INCOMPLETE` blocks exactly like `FAIL`.

The harness completion marker `A24B3_800_ISOLATED_HARNESS_COMPLETE` is emitted only for a complete harness `PASS`. The runner marker `A24B3_900_ISOLATED_RUNNER_COMPLETE` is emitted only after zero exit, no ERROR/FATAL diagnostic, the harness marker, exact JSON contract validation, and independent `results.json` digest verification.

## Frozen evidence schema

`results.json` must contain: schema version; unique run ID; UTC capture time; masked topology; Node/npm/approved dependency versions; attestation/runner/harness hashes; numeric process exit code; stdout/stderr references; semantic assertion records; identity/PID evidence; denial matrix with expected and actual SQLSTATE; contamination matrix; lock evidence; cancellation/timeout/disconnect evidence; quarantine log; cleanup status; absence-attestation status; independent-review verdict; per-case results; and final status.

`results.sha256` binds the exact UTF-8/LF bytes of `results.json` and is independently recomputed by the runner. `step-results.txt` records safe runner lifecycle, expected/actual digest, and bounded termination fields on every path where the approved evidence location is available. A deterministic terminal marker states when no safe evidence path could be proven. Missing mandatory evidence, artifact hash, cleanup PASS, absence-attestation PASS, or independent approval produces `FAIL` or `INCOMPLETE`.

## Runner result state machine

- Exit `0` plus valid `PASS` evidence and marker: runner may PASS.
- Exit `0` plus valid `FAIL`/`INCOMPLETE` evidence: integrity is recorded, then runner fails closed.
- Nonzero exit plus valid `FAIL`/`INCOMPLETE` evidence: digest and JSON contract are validated first, then runner fails closed on the native exit.
- Any exit plus missing, malformed, duplicate, or digest-mismatched evidence: runner fails closed as evidence-invalid.
- Timeout plus valid retained evidence: integrity is validated after confirmed bounded termination, then timeout fails closed.
- Timeout plus missing/invalid evidence or uncertain termination: runner fails closed and records quarantine/termination state where a safe path exists.

The runner uses the same pure result-contract and classification functions for deterministic source fixtures covering nonzero valid `INCOMPLETE`, digest mismatch, malformed JSON, wrong run ID, wrong schema, missing mandatory fields, timeout with valid retained evidence, and timeout with missing/invalid evidence. These fixtures launch no process and perform no network or database operation.

Retained-results validation is independent of indentation, newline style, and top-level property order. A pre-parse structural token scan extracts only top-level JSON object keys, decodes escaped key names with the platform JSON parser, and rejects every duplicate top-level key without matching property-like text inside string values or nested objects. Post-parse checks require the exact mandatory property inventory and expected object, array, string, and integer shapes.

Every serialized result and derived matrix is built from one authoritative bounded projection. Version evidence is single-line, normalized, at most 64 characters, and restricted to a version grammar; missing optional packages are recorded as `NOT_INSTALLED`.

Fixed synthetic projection fixtures require `token`, `password`, `connectionString`, `rawHost`, `stack`, `arbitraryPayload`, and `queryText` to remain absent while a safe neighboring field remains present. Node, npm, `pg`, optional package, evidence-schema, and harness-tool versions all pass through the same validator before serialization.

Evidence remains below the Git-ignored `database-reconciliation/core-v2/P2D/evidence/` root. Credentials, complete URLs, raw hostnames, tokens, certificates, environment values, arbitrary SQL, business identifiers/data, P2D.20 payloads, and unsafe exception details are prohibited.
