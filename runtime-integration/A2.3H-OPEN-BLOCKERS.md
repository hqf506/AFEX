# A2.3H Open Blockers

## Provider confirmation blockers

- Custom dedicated LOGIN support.
- Exact SET-only membership options and hosted restrictions.
- Explicit transaction backend pinning.
- `SET ROLE` and `SET LOCAL ROLE` support and identity semantics.
- Backend sanitation after commit, rollback, cancellation, and disconnect.
- Transaction advisory locks and prepared-statement restrictions.
- Required TLS mode and Vercel IPv6/IPv4 compatibility.
- Vercel TCP, warm reuse, termination, scaling, duration, memory, and observability behavior.

## Runtime-test blockers

- Identity transition/reset proof.
- Sequential and concurrent contamination resistance.
- Rollback, cancellation, abrupt-disconnect, timeout, and commit-uncertainty behavior.
- Advisory locks, prepared statements, pool exhaustion, credential rotation, membership revocation, and TLS validation.
- Complete cleanup and absence attestation.

## Capacity, secret, and operational blockers

- Current database usage and reserved capacity.
- Expected Production order concurrency and safe per-instance/global pool limits.
- Dedicated credential name/scope, Preview exclusion, rotation, overlap, emergency revoke, and redeploy process.
- Sanitized metrics, correlation, alerting, retention, stop conditions, and disabled Production smoke evidence.

## Prohibited until closure

No SQL execution, role creation, package installation, database connection, connection factory, role wrapper, P2D.20 wiring, Production integration, service-role fallback, dual write, route activation, or feature enablement.

## Current disposition

A2.3H documentation is ready for review. Provider questions have not been submitted, tests have not been implemented or run, and the transaction-pool architecture remains unapproved.
