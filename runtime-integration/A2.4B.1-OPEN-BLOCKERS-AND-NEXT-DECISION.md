# A2.4B.1 Open Blockers and Next Decision

Status: TEST_DESIGN_APPROVED

## Decision

`TEST_DESIGN_APPROVED`

The transaction-pooler topology is not rejected because the documented transaction-lending model supports a bounded isolated test. More provider evidence would be useful but is not a prerequisite to designing that test. Provider statements alone cannot approve runtime use.

## Open blockers

1. No independently reviewed disposable setup, attestation, or cleanup SQL package exists.
2. No package installation is authorized; `pg` and `@vercel/functions` remain absent/unapproved for this test.
3. No isolated test harness exists or is authorized.
4. No dedicated short-lived test credential or approved secret lifecycle exists.
5. `SET LOCAL ROLE` behavior through Supavisor remains undocumented and unproven.
6. Cleanup after commit, rollback, cancellation, timeout, and disconnect remains unproven.
7. Sequential and concurrent backend contamination resistance remains unproven.
8. Transaction advisory-lock exclusion and release remain unproven.
9. Exact TLS, region, capacity, pool, timeout, and observability values remain unfrozen.
10. Evidence storage, operator authority, execution window, reviewers, and cleanup owner require organizational approval.

## Prohibited conclusions

- This decision does not close G1–G12.
- It does not approve session-scoped `SET ROLE`.
- It does not approve Production credentials, runtime implementation, adapter activation, P2D.20 invocation, routes, deployment, or traffic.
- It does not authorize SQL creation/execution, database contact, package installation, environment changes, staging, commit, or push.

## Exact next phase

Proceed only to an externally reviewed **A2.4B.2 — Disposable Runtime Test Package Design**. That phase may design, but must not execute without further authorization:

1. Setup, read-only attestation, cleanup/revocation, and post-cleanup attestation artifacts within the boundaries in A2.4B.1.
2. A fixed-operation isolated harness and dependency proposal.
3. An operator runbook with credential handling, evidence masking, STOP conditions, quarantine, and cleanup.
4. A manifest binding every artifact to its reviewed hash.

Package installation, SQL execution, database contact, provider contact, and test execution require later explicit approvals after external review.
