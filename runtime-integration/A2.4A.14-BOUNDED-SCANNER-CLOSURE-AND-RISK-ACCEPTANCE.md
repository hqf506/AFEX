## Narrow corrections

- Added stable rule `adapter_dynamic_surface_construct`.
- The rule rejects adapter-reachable `eval`, `new Function`, `Proxy`, `Reflect`, mutation-oriented `Object` helpers, nonliteral dynamic imports, explicit `any`/`unknown` casts, decorators, call-based mixin heritage, class/constructor factories, constructor containers, object-held class/factory surfaces, declared classes passed through generic calls, and direct prototype assignment.
- Added isolated fixtures for all four deferred constructor/factory forms and representative dynamic constructs.
- The rule is syntax-level and deterministic; it does not perform recursive general-purpose type evaluation.

## Returned tuple/rest diagnostics

A call used directly as a spread source now materializes its statically returned array under a stable synthetic container path. Provenance includes the original member, returned container construction, return site, receiving spread/index, rest binding, indexed/call use, alias, and final export coordinates. The rule ID remains `adapter_generic_query_surface`.

## Policy bans

Production adapter modules prohibit:

- `eval`, `new Function`, `Proxy`, and Reflect-based capability access;
- nonliteral dynamic imports and runtime-generated capability names;
- `Object.assign` or prototype/property mutation to assemble adapter/transport surfaces;
- class/constructor factories, constructor containers, and class expressions in adapter object maps;
- explicit `any`/`unknown` casts that erase trusted-boundary information;
- dynamic prototype mutation, decorators, and mixin-generated trusted surfaces;
- generic database APIs, dynamic code generation, symbols used to hide capability names, and nonreviewed production exports.

Syntax checks are supplemented by path allowlists, production-export restrictions, CI execution of the scanner, and mandatory independent review for trusted-boundary changes.

## Final scanner contract

### A. ENFORCED_BY_SCANNER

- Direct and transitive local imports, wrappers, barrels, CommonJS, literal dynamic imports, and cycles.
- Forbidden packages, environment access, P2D.20 calls, caller-role targets, fake reachability, and ledger/application boundaries.
- Enumerated aliases, functions, methods, getters, computed literals, object/tuple spreads, indexed/rest containers, conditional/nullish layouts, class expressions, inheritance, and static/instance override namespaces.
- The explicit dynamic-surface syntax bans listed above.
- Exact adapter diagnostics, deterministic ordering, source coordinates, and stable rule IDs.

### B. PROHIBITED_BY_POLICY_AND_REVIEW

- Class/constructor factory abstraction in production adapter code.
- Constructors in generic containers or object registries.
- Runtime-generated property/capability names, prototype mutation, monkey-patching, decorators, and mixins.
- Information-erasing casts, dynamic module selection, generated code, symbol-hidden surfaces, and generic database APIs.

### C. OUTSIDE_ABSOLUTE_STATIC_PROOF

- Runtime values supplied by external code, deliberately generated/evaluated code, runtime monkey-patching, native/add-on behavior, and semantics erased before entering the scanned graph.
- These are not claims of safety by static proof; they are excluded by architecture, source review, CI, module allowlists, and the hard-disabled factory.

## Future finding threshold

- **BLOCKER:** active production reachability; credential, authority, route, database activation, or direct actual-repository bypass.
- **HIGH:** realistic ordinary coding pattern reproducible in repository-reachable trusted modules without a compensating control.
- **MEDIUM:** defense-in-depth, diagnostic, coverage, or false-positive defect with compensating controls.
- **LOW:** documentation or maintainability defect without security-boundary impact.
- A theoretical AST construction with no repository reachability and an explicit policy ban is not automatically HIGH.
