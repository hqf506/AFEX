## Corrections

### Tuple-rest provenance

Array binding now materializes a statically sized suffix container for a rest binding. Callable and getter/value provenance is copied from every retained source index to the corresponding rest index. Nested array binding patterns recurse against their indexed source container, including readonly and assertion-wrapped tuple literals.

### Conditional and nullish spread alternatives

Spread registration maintains a set of possible output offsets. Each conditional/nullish source alternative contributes provenance at its own possible resulting indexes; alternatives are no longer concatenated into one fictitious layout. Subsequent elements are mapped from every possible output offset. Diagnostic provenance names the contributing source alternative, source index, resulting index, and final exposure.

### Class factories and returned constructors

Function declarations, function expressions, and arrows now expose statically resolvable returned class surfaces. Inline returned class expressions receive stable synthetic factory identities. Returned named class/constructor aliases and multi-hop factory calls propagate their static, instance, getter, field, inheritance, and construction surfaces. Exported factories expose the returned surface to root/import-chain scanning.

### Namespace-bound class expressions

Variable-bound class expressions use their namespace-qualified identity. Nested namespace expressions, namespace aliases, static access, construction, exports, barrels, CommonJS surface propagation, and cycles therefore retain the same class surface identity when statically resolvable.

### Static and instance override separation

Class registration now builds independent declared-name sets for static and instance members. Inheritance suppression is applied only inside the matching namespace. Nearest effective overrides remain authoritative within their own namespace.

## Remaining static limitations

The scanner does not claim complete semantic proof for runtime-generated factories, dynamically selected constructors, prototype mutation, monkey-patching, generated code, symbol-keyed runtime surfaces, or information-erasing behavior. A2.4A.14 introduces syntax-level policy enforcement for practical `eval`, `new Function`, `Proxy`, `Reflect`, nonliteral import, prototype mutation, factory/container, decorator/mixin, and explicit `any`/`unknown`-cast forms while retaining mandatory source and independent review for behavior outside absolute static proof.
