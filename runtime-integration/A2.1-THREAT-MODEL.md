# AFEX ERP / POS — A2.1 Trusted Adapter Threat Model

Status: DESIGN ONLY

## 1. Assets and trust zones

Assets are authenticated identity, tenant/branch isolation, immutable command
identity, canonical intent, idempotency identity, authorization evidence,
database credentials, fingerprints, response snapshots, and Core V2 ledgers.

Trust zones: browser/untrusted input; authenticated application server; trusted
adapter; restricted managed-LOGIN transport; SECURITY DEFINER P2D.20; durable
ledger. Crossing a zone always requires exact validation and no implicit trust.

## 3. Abuse cases

### Same key, changed payload

The database must return `fingerprint_conflict`. The adapter must not retry with a
new key, execute the existing command, or reveal the stored fingerprint.

### Timed-out first acquisition

The adapter cannot infer rollback. It records an ambiguous transport failure and
later resolves using the same actor/scope/key/canonical bytes. Execution begins
only from an unambiguous `created` contract under a later Executor design.

### Forged sealed object

A structurally identical object fails A1 provenance because only the exact fresh
object registered by the sole sealer is accepted. Casts cannot create runtime
provenance and are statically prohibited.

### Metadata manipulation

Excluded metadata cannot affect fingerprint identity. Included
`metadata.source_channel` does. All metadata remains exact-allowlist validated;
forbidden tracing, features, and payment evidence are rejected.

## 4. Detection and response baseline

Critical alerts: malformed DB rows, unknown dispositions, authority-seal failure,
unexpected DB diagnostics, evidence-binding failures, scanner bypass, or secret
detection. These stop activation and require security review.

Warning thresholds: timeout, transient transport, conflict, repeated in-progress,
credential failure, and normalization failure. Telemetry contains correlation and
stable categories only.

No threat response falls back to legacy mutation, invents an idempotency key,
retries execution, exposes raw diagnostics, or edits durable records.

## 5. Residual-risk conclusion

The principal unresolved risks are managed-LOGIN/client evidence, full authority-
evidence retrieval, Unicode parity, ambiguous transport resolution, retention
policy, and the route-level `in_progress` product contract. They are explicit
gates, not implied implementation choices.
