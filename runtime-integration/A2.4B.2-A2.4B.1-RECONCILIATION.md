# A2.4B.2 A2.4B.1 Reconciliation

Status: DIRECT-EXECUTE AMENDMENT; A2.4B.1 RETAINED AS HISTORICAL EVIDENCE

## Purpose

A2.4B.1 accurately recorded why transaction-local role switching was not approved. This amendment does not rewrite that history. It identifies which conclusions remain applicable after selecting a dedicated LOGIN with direct EXECUTE on the exact P2D.20 SECURITY DEFINER entrypoint.

## Conclusion inventory

| A2.4B.1 conclusion | Disposition | Direct-EXECUTE interpretation |
|---|---|---|
| Supabase Transaction Pooler is preferred for Vercel/serverless traffic | RETAINED | It remains the candidate connection topology. Preference is not proof of AFEX runtime correctness. |
| One bounded process-global `pg` Pool is recommended | RETAINED | Pool reuse still requires capacity, cancellation, quarantine, and contamination controls. |
| `attachDatabasePool` is supported | RETAINED | It remains future Vercel lifecycle guidance if the selected harness/runtime needs it. |
| Persistent prepared statements are prohibited in transaction mode | RETAINED | The direct-EXECUTE model does not change this prohibition. |
| Explicit-transaction backend pinning must be proven | NARROWED | Role activation no longer depends on it, but P2D.20 transaction semantics and advisory locks still require proof through the pooler. |
| `SET LOCAL ROLE` requires isolated testing | SUPERSEDED | The application path will not use role switching; the test is removed. |
| Role-state cleanup before backend reuse requires testing | SUPERSEDED | No application role transition exists. Identity and general connection-state cleanup remain required. |
| Transaction advisory-lock behavior requires testing | STILL_REQUIRED | P2D.20 concurrency behavior is independent of the caller privilege model. |
| Cancellation and unknown-outcome behavior requires testing | STILL_REQUIRED | Direct EXECUTE does not resolve ambiguous send/commit outcomes. |
| Sequential and concurrent contamination require testing | NARROWED | Role-leak cases are removed; transaction, GUC, prepared-state, result, identity, and request-isolation checks remain. |
| Disposable LOGIN plus SET-only NOLOGIN role environment | SUPERSEDED | Replace it with a disposable LOGIN having direct EXECUTE on one harmless SECURITY DEFINER test entrypoint and no membership. |
| Uncertain connections must be quarantined | RETAINED | Cancellation, timeout, disconnect, protocol, and transaction ambiguity still require destruction rather than reuse. |
| No package, SQL, credential, database, P2D.20, or activation authorization | RETAINED | This phase remains documentation-only. |

## Historical boundary

A2.4B.1 remains authoritative for the evidence available at that time and for rejection of undocumented role switching. Its stated next phase for a role-switch test package is cancelled. It must not be used as authorization to create membership, run `SET ROLE`, or run `SET LOCAL ROLE`.
