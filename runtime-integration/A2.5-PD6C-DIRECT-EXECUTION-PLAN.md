# A2.5 PD.6C Direct PostgreSQL Evidence Execution Plan

## Boundary and architecture

`A2.5-PD6C-DIRECT-RUNNER.mjs` is inert when imported and calls `main()` only when directly invoked. It imports the merged PD.5 `RealDriverAdapter` through the reviewed PD.6 harness and reuses the reviewed trusted operation descriptors, `createBoundedResult()`, `withLockControl()`, and `TYPE_FIXTURE_BASELINE`. It does not duplicate transaction-status, rollback, release, error-vocabulary, or SQL authority.

Implementation validation is fake-only. No PostgreSQL connection or SQL execution is authorized until the runner passes independent review and the operator separately starts the execution phase.

## Fixed identity, credentials, and pool

The future endpoint is fixed to `127.0.0.1:55432`, database `afex_a25_pd6`, user `afex_a25_pd6_runner`, and application name `afex-a25-pd6c-direct-runner`. The reviewed harness freezes max 1, min 0, connection timeout 5000 ms, idle timeout 1000 ms, maximum lifetime 30 seconds, exit-on-idle, keepalive, and disabled TLS override.

Only `AFEX_A25_PD6_PASSWORD` supplies the password. Missing, empty, or whitespace-only values fail before harness construction. `PGPASSWORD`, `PGUSER`, `PGHOST`, `PGPORT`, `PGDATABASE`, `DATABASE_URL`, Supabase variables, `.env`, application configuration, and process-environment merging are excluded. The password is never returned, logged, persisted, digested, or retained in evidence.

## External output

`AFEX_A25_PD6_OUTPUT_DIR` is mandatory, absolute, and outside the repository, current worktree, and dirty source worktree. Containment uses path-aware comparison, is case-insensitive only on Windows, and canonicalizes the nearest existing ancestor with `realpath` before re-appending a non-existing suffix. Existing symlink, junction, and reparse aliases are therefore resolved; inability to establish a canonical path fails closed. Textual-prefix siblings remain allowed.

Only `pd6c-results.json`, `pd6c-digest.txt`, and `pd6c-summary.txt` are created. Any pre-existing final or current-process temporary name blocks publication without overwrite. After aggregate validation and digest generation, all three contents are prepared in fixed per-process temporary files before any final rename. If a prepare or publish step fails, every temporary and every final published by the current attempt is removed on a best-effort basis and the run fails. The summary is published last. A completed evidence set requires all three final files from the same successful publication; results, digest, or summary alone are never completion authority. Evidence contains no output path, password, URL, SQL, raw error, stack, PID, duration, clock, process data, or transient object identity.

## Baseline and version authority

Before mutation the runner uses only `READ_SERVER_VERSION`, `READ_LOCK_TARGET`, `READ_TYPE_FIXTURE`, `READ_TRANSACTION_FIXTURE`, and `READ_STATUS_FIXTURE`. It requires lock row `(1, pd6-lock-target)`, transaction row `(1, 0, pd6-transaction-baseline)`, status row `(1, 0, pd6-status-baseline)`, and the exact reviewed type baseline. Drift stops execution without repair. The bounded numeric value returned by `READ_SERVER_VERSION` populates the existing `postgres_version` field; no banner, platform, build metadata, or PID is retained.

## Restoration

Restoration uses only `UPDATE_TRANSACTION_FIXTURE` with `(0, pd6-transaction-baseline)` and `UPDATE_STATUS_FIXTURE` with `(0, pd6-status-baseline)`, followed by their reviewed reads. No INSERT, DELETE, TRUNCATE, DDL, cleanup SQL, ad hoc SQL, or dynamic identifier exists. A restoration error or verification mismatch is terminal and blocks later trusted output.

## Scenario lifecycle authority

Statement timeout begins a transaction, applies `SET_LOCAL_STATEMENT_TIMEOUT`, executes `SAFE_DELAY`, requires retained `57014`/`PG_STATEMENT_TIMEOUT`, rolls back at most once, observes safe sanitation, and releases through the adapter. There is no cancellation or retry.

Lock timeout uses `withLockControl()` for the bounded dedicated public `pg.Client` control lifecycle. The borrower begins, applies `SET_LOCAL_LOCK_TIMEOUT`, executes `LOCK_TARGET_UPDATE`, requires retained `55P03`/`PG_LOCK_TIMEOUT`, rolls back once, sanitizes, and releases. The control always follows its bounded rollback/end policy.

Permission scenarios use only the four denial operations. CREATE denials are followed by their fixed absence verifiers even when the denied operation unexpectedly succeeds or has the wrong bounded classification; presence fails closed. Unexpected success, a wrong failure code, or cleanup uncertainty terminalizes the lease, stops the run, and cannot produce scenario evidence. Transactional rollback is attempted at most once where safe, but no DROP or other cleanup DDL is introduced. `42501` is not retained because it is outside the frozen PD.5 allowlist. No raw error or cleanup DDL is retained or executed.

Type scenarios record the actual value class without coercion or global parser changes. int8 and numeric remain strings; bytea remains Buffer; arrays retain order; JSON/JSONB remain decoded logical objects; null remains null. Timestamp observations are Date-class observations only. Exact `678901` microsecond authority remains exclusively in the reviewed logical projections, and timestamp without time zone is not assigned UTC semantics.

Destruction/replacement uses the adapter destructive release and then proves a subsequent safe acquisition/read. Object identity is transient and no PID is retained. Borrower mismatch uses opaque local owner labels and the PD.5 ownership contract; it passes only for exact `PG_IDENTITY_MISMATCH` followed by `DESTROY_RELEASE`. Second rollback requires the initial exact `PG_QUERY_FAILED`, one successful external rollback, and exact `PG_RELEASE_STATE_INVALID` from the rejected second attempt while the external count remains one. Arbitrary exceptions cannot satisfy either scenario. No retry is permitted.

## Results, aggregate schema, and digest

Every scenario passes `createBoundedResult()` before retention. Invalid evidence terminates execution. `A2.5-PD6C-DIRECT-EVIDENCE.schema.json` closes the aggregate to schema version, driver/server versions, endpoint class, exact count/order, bounded results, aggregate pass, and digest.

The SHA-256 digest uses a recursively key-sorted canonical serializer over every aggregate field except `canonical_digest`. It includes schema version, driver version, observed PostgreSQL version, endpoint class, scenario order, bounded results, and aggregate pass. It excludes paths, credentials, clocks, durations, raw errors, process data, PIDs, object identity, and temporary filenames.

## Fail-fast and exit contract

Credential, output-path, connection, baseline, unsafe scenario, restoration, schema, digest, write, and unexpected failures stop. Every acquired expected-failure lease enters one terminalization coordinator: proven rollback/sanitation may end in normal release, while unexpected success, wrong classification, or cleanup uncertainty forces destructive disposition. No path intentionally throws before terminalization is attempted. No uncertain connection or transaction state permits continuation and there is no automatic retry.

Pool shutdown is deadline-bounded to 2000 ms and runs only after scenario leases and lock control have settled. Successful shutdown occurs before evidence publication. A rejection or non-settling `pool.end()` produces bounded scenario-safety failure and cannot publish success evidence. Exact exits are: success `0`, credential `10`, output path `11`, connection `12`, baseline `13`, scenario safety `14`, restoration `15`, schema `16`, digest `17`, output write `18`, unexpected `19`. Standard output is one bounded sanitized summary line without a stack or secret.

The first authorized human run returned ambiguous `CONNECTION_FAILED` / exit `12`, while independent operator checks proved the exact TCP endpoint, credential, database, role, and non-SSL `psql` connection succeeded. Static review found that the former connection catch also covered baseline queries, sanitation, release, and validation. The runner now freezes baseline-stage diagnostics to `POOL_CONNECT_FAILED`, `BASELINE_OPERATION_FAILED`, `BASELINE_SANITATION_FAILED`, `BASELINE_RELEASE_FAILED`, and `BASELINE_VALIDATION_FAILED`. Only pool checkout uses exit `12`; the other four use baseline exit `13`. Operation diagnostics may retain only one of the five fixed baseline operation identifiers, and validation diagnostics may retain only a closed fixture target. Raw errors, SQL, values, credentials, and connection details remain excluded. This ambiguous first run is historical and was superseded by the accepted successful run below.

## Manual PowerShell procedure — do not run during implementation or review

The environment variables below are plaintext within the process environment while set. The SecureString conversion is transient and neither value may be printed.

```powershell
Set-Location -LiteralPath 'C:\Users\NSC-LUA\Desktop\leather-fix-erp-a2-5-pd6c-direct-pg\runtime-integration'
$pd6cEvidenceDir = 'C:\AFEX-Evidence\A2.5-PD6C'
New-Item -ItemType Directory -Force -Path $pd6cEvidenceDir | Out-Null
$pd6cSecurePassword = Read-Host 'AFEX A2.5 PD6 runner password' -AsSecureString
$pd6cCredential = [System.Net.NetworkCredential]::new('', $pd6cSecurePassword)
$env:AFEX_A25_PD6_PASSWORD = $pd6cCredential.Password
$env:AFEX_A25_PD6_OUTPUT_DIR = $pd6cEvidenceDir
node .\A2.5-PD6C-DIRECT-RUNNER.mjs
$pd6cExitCode = $LASTEXITCODE
Remove-Item Env:AFEX_A25_PD6_PASSWORD -ErrorAction SilentlyContinue
Remove-Item Env:AFEX_A25_PD6_OUTPUT_DIR -ErrorAction SilentlyContinue
$pd6cCredential = $null
$pd6cSecurePassword = $null
[GC]::Collect()
Write-Output "PD6C exit code: $pd6cExitCode"
Write-Output "Results: $pd6cEvidenceDir\pd6c-results.json"
Write-Output "Digest: $pd6cEvidenceDir\pd6c-digest.txt"
Write-Output "Summary: $pd6cEvidenceDir\pd6c-summary.txt"
```

Exit `0` means all 30 scenarios passed, aggregate validation and digest succeeded, and all three evidence files were written. Any nonzero value is failure authority and prohibits treating output as successful evidence.
