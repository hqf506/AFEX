# A2.3 Future SQL and Implementation Plan

Status: design inventory only; contains no executable SQL

## Future database units

| Unit | Preconditions | Intended effect | Risk and rollback | Required attestation |
|---|---|---|---|---|
| LOGIN creation | Approved topology, name, owner, limits, credential custody | Create isolated finite-lived application LOGIN | Partial identity/credential exposure; rollback disables/drops only if no dependency | Exact attributes, no ownership/ACL/membership. |
| Membership edge | LOGIN and PostgreSQL 17.6 option proof | SET-only membership in Runtime | Wrong direction/options broaden authority; rollback exact edge | One allowed row; no others; postgres edge unchanged. |
| Role configuration | Frozen safe baseline | Defense-in-depth defaults | Session behavior changes | Exact config inventory. |
| Runtime entrypoint verification | P2D.20 frozen hash/signature | Confirm Runtime retains exact direct EXECUTE | Unexpected ACL or owner drift | Signature, owner, SECURITY DEFINER, search path, ACL. |
| PUBLIC closure | A2.1T consumers and managed-object approval | Remove only separately approved unrelated exposure | Break legacy/managed callers | Per-signature before/after manifest and rollback. |
| Connection-limit policy | Capacity plan approved | Enforce finite LOGIN concurrency | Too low causes outage; too high exhausts DB | Exact role limit and load proof. |
| Postcondition attestation | All units reviewed | Fail-closed installed-state proof | None; read-only | Role graph, ACL, ownership, function, managed-role invariants. |
| Revocation/rollback package | Before enablement | Disable LOGIN/edge safely without mutating durable commands | Active sessions/unknown calls | Gate off, sessions terminated, reachability zero. |

Each future mutation is a separately reviewed executable artifact with preflight, transaction behavior, exact hashes and manual evidence. This document does not authorize it.

## Future application units

1. Package/driver ADR and lockfile review.
2. Server-only configuration module with conceptual dedicated connection variables and hard disabled gate.
3. Non-exported bounded connection factory.
4. Transaction/identity/role activation wrapper implementing the lifecycle contract.
5. Exact P2D.20 domain method with no generic API.
6. Authorization Context builder and sealed request binding.
7. Stable result/error mapping and redacted observability.
8. Unit/type/mock tests and import-graph scanner.
9. Isolated transaction-pool contamination/concurrency/unknown-outcome tests.
10. Preview smoke test with separate non-Production identity.
11. Production preflight, disabled deployment and zero-call observation.
12. Explicit cutover gate selecting one engine before mutation.

No unit may wire P2D.20 until database identity, pool and cleanup attestations pass. No unit may modify the legacy path during the disabled skeleton phase.
