# A2.4B.1 Future SQL and Harness Boundaries

Status: BOUNDARIES ONLY; NO SQL OR HARNESS AUTHORIZED

## Future SQL packages

Three separately reviewed packages are required. This document contains no SQL content.

### Setup package

May define only the disposable LOGIN, disposable NOLOGIN role, exact SET-only membership, harmless constant/catalog-only function, least-privilege ownership and ACL closure, and fail-closed pre/post verification. It must refuse pre-existing conflicting objects and must not reference business tables or P2D.20.

### Attestation package

Must be read-only and independently verify role attributes, membership options, ownership, function signature/body boundary, ACLs, absence of business access, and absence of unrelated objects. It must produce a unique completion marker and fail closed.

### Cleanup and revocation package

May only revoke the disposable credential/membership and remove the disposable function and roles in dependency-safe order. It must fail closed on unexpected dependencies or ownership and be followed by a read-only absence attestation.

Setup, attestation, and cleanup require separate external SQL review and explicit operator authorization. No password or connection material may appear in any artifact.

## Future harness boundary

- A future `pg` dependency may be proposed only in a separately approved package-change phase.
- A future `@vercel/functions` dependency may be proposed only if the chosen Vercel execution environment requires `attachDatabasePool`.
- The harness may connect only through the reviewed Supabase transaction-pooler endpoint class.
- One process-global, bounded Pool may be used, with bounded checkout/connect/statement/idle timeouts and deterministic drain behavior.
- Persistent prepared statements and named statements are prohibited.
- The harness must expose fixed typed test operations, not a generic query, execute, raw SQL, RPC, table, schema, or transaction capability to application code.
- Statements, role names, function names, and test cases must be compile-time allowlisted; operator-supplied SQL is prohibited.
- No imports or calls from application routes, POS, Admin, Runtime activation, Executor, background jobs, or legacy order flow are permitted.
- No P2D.20 call or business table access is permitted.
- Unknown connections must be quarantined and destroyed; cleanup failures drain the pool and fail the run.
- Evidence output must be local, ignored by Git, masked before review, and hashed after capture.

## Credential and configuration boundary

The future harness may read only a dedicated short-lived test credential through an approved server-only mechanism. It must never print the credential, full connection URL, private hostname, certificate material, or raw environment values. Configuration evidence is limited to masked endpoint class, TLS mode label, pool bounds, runtime version, and presence booleans.

## Explicit exclusions

Production transport, Core V2 adapter activation, feature flags, application routes, customer/order/payment/inventory data, real idempotency keys, provider CLI use, migrations against business objects, and deployment are outside this design.
