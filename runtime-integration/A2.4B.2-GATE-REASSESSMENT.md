# A2.4B.2 Gate Reassessment

Status: DIRECT-EXECUTE MODEL SELECTED; ACTIVATION BLOCKED

| Gate | Direct-EXECUTE classification | Rationale and closure |
|---|---|---|
| G1 Dedicated identity | REQUIRES_SQL_ATTESTATION | A dedicated LOGIN is still required; exact attributes, ownership, expiry, connection limit, and effective privileges must be attested. |
| G2 Membership graph | REMOVED_BY_ARCHITECTURE | The application has no membership and performs no SET ROLE. Zero membership remains an attested denial. |
| G3 Transaction pinning | SIMPLIFIED | It no longer protects role activation, but explicit transaction behavior and transaction advisory locks still require runtime proof. |
| G4 Scoped role activation | REMOVED_BY_ARCHITECTURE | No `SET ROLE` or `SET LOCAL ROLE` exists in the application path. |
| G5 Cleanup/reuse safety | SIMPLIFIED | Role cleanup is removed; cancellation, transaction state, GUC/prepared state, quarantine, and cross-request isolation still require tests. |
| G6 TLS/network | PARTIALLY_PROVEN | Provider direction exists; exact verified TLS, endpoint, IP/region, and project configuration remain blocked. |
| G7 Vercel Node compatibility | PARTIALLY_PROVEN | Driver/pool guidance exists; package, Node, cancellation, preparation-disabled, and lifecycle behavior remain untested. |
| G8 Capacity | BLOCKED | Finite LOGIN and pool limits, current utilization, concurrency, checkout timeout, and database budget are not approved. |
| G9 Secret lifecycle | SIMPLIFIED | One dedicated LOGIN secret remains; provisioning, server-only scope, rotation, emergency disablement, and revocation require approval and tests. |
| G10 Cancellation/unknown outcomes | REQUIRES_RUNTIME_TEST | Direct EXECUTE does not remove send, cancellation, timeout, disconnect, or commit ambiguity. |
| G11 Advisory locks | REQUIRES_RUNTIME_TEST | P2D.20 transaction advisory-lock behavior through the pooler remains unproven. |
| G12 Observability/baseline | BLOCKED | Safe lifecycle, pool, call, outcome, quarantine, revocation, and denial evidence must be implemented and reviewed. |

## Required denial attestations

G1, G2, and the SECURITY DEFINER boundary require SQL attestation of no membership, no ownership, no relation/sequence access, no schema CREATE, no unrelated function execution, no PUBLIC/default leakage, and the exact P2D.20 EXECUTE edge.

## Architecture effect

The direct-EXECUTE model removes the unproven role-activation dependency and materially simplifies cleanup. It does not prove the transport, transaction pooler, P2D.20 runtime behavior, cancellation, advisory locks, capacity, secrets, or observability.
