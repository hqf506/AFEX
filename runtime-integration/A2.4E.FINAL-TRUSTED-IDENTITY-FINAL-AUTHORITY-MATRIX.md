# Trusted Identity Final Authority Matrix V4

## 1. Sole authority and closed-world rule

This document is the sole normative authority for Trusted Identity implementation. It completely replaces every earlier version of this matrix and every historical S4.x or FINAL.Rx authority. Historical documents are traceability only. One active version exists per contract. Aliases, compatibility layers, caller-selected policy, implicit applicability, implementation-defined fields, and runtime-generated oracle values are forbidden.

The engine contract is `A24E_FINAL_V4`. Every registry, schema, profile, transition, hash projection, artifact, and fixture named below is closed. An unlisted field, row, state, transition, artifact, membership, failure code, or authority path fails closed as `EVIDENCE_INVALID` unless an earlier state proves no process/database effect, in which case it reaches `FAILED_PREMUTATION_CANDIDATE` and must still pass the V4 evidence gates before terminal publication.

## 2. Canonical primitives and serialization

| type | exact rule |
|---|---|
| `str` | JSON string; Unicode NFC; no NUL; no unpaired surrogate |
| `run` | `str` matching `^[A-Za-z0-9._-]{1,128}$` |
| `role` | empty only where explicitly allowed, otherwise `^afex_core_test_login_[0-9]{14}_[0-9a-f]{8}$` and at most 63 UTF-8 bytes |
| `oid` | signed Int64 JSON integer; zero only for the frozen empty identity |
| `i32` / `i64` | signed integer without exponent or fraction |
| `bool` | JSON `true` or `false` |
| `utc` | exact UTC `yyyy-MM-ddTHH:mm:ss.fffZ` |
| `hash` | exactly 64 lowercase hexadecimal SHA-256 characters |
| `hash?` | `hash` or JSON null only where declared |
| `role?` | valid `role` or JSON null; empty string is not persisted identity |
| `oid?` | positive `oid` or JSON null; zero is not persisted identity |
| `arr<T>` | ordered JSON array of `T`; duplicate members forbidden where uniqueness is stated |
| `obj` | closed ordered JSON object |

All objects serialize in their schema field order as UTF-8 without BOM, NFC, minimal JSON escaping, no insignificant whitespace, no CR, and no trailing LF. JSONL is the canonical object followed by exactly one LF per row, including the last. Object keys are emitted exactly once. Numbers are decimal. SHA-256 always hashes the exact canonical bytes named by the projection. No projection contains its own hash.

## 3. ExecutionState and state registry

The sole immutable state schema is `A24E_FINAL_V4_EXECUTION_STATE` with these fields in order:

`schema_version:str, contract_version:str, run_id:run, current_state:str, next_sequence:i64, transition_records:arr<A24E_FINAL_V4_TRANSITION_ROW>, classification_records:arr<A24E_FINAL_V4_CLASSIFICATION_ROW>, stage_authorities:arr<A24E_FINAL_V4_STAGE_ROW>, role_name:str, role_oid:i64, trusted_identity_record_hash:hash?, identity_bound:bool, identity_required:bool, identity_authoritative:bool, cleanup_result:str, post_cleanup_result:str, admitted_logical_ids:arr<str>, terminal_record_type:str`.

The state is copied on every reducer call; input and prior arrays are defensively copied and never mutated. The in-memory empty identity is exactly `role_name=""`, `role_oid=0`, `trusted_identity_record_hash=null`, and all three identity booleans false. Persisted downstream records represent absence only as `identity_present=false`, `role_name=null`, `role_oid=null`, `trusted_identity_record_hash=null`, and `identity_artifact_sha256=null`. Bound identity requires `identity_present=true` and all four identity values non-null. Every other combination is invalid.

States are exactly:

`NOT_STARTED`, `DEPENDENCIES_MISSING_CANDIDATE`, `PREFLIGHT_PASSED`, `CREDENTIAL_READY`, `CREATE_STARTED`, `CREATE_PREMUTATION_FAILED`, `CREATE_ROLLED_BACK`, `CREATE_COMMITTED`, `CREATE_OUTCOME_UNKNOWN`, `ROLE_ABSENCE_VERIFICATION_STARTED`, `ROLE_ABSENCE_VERIFIED`, `ROLE_ATTESTATION_STARTED`, `ROLE_ATTESTED`, `ROLE_ATTESTATION_FAILED`, `HARNESS_STARTED`, `HARNESS_PASSED`, `HARNESS_FAILED`, `CLEANUP_REQUIRED`, `CLEANUP_STARTED`, `CLEANUP_PASSED`, `CLEANUP_FAILED`, `POST_CLEANUP_STARTED`, `POST_CLEANUP_PASSED`, `POST_CLEANUP_RESIDUE`, `FAILED_PREMUTATION_CANDIDATE`, `FAILED_CLEANUP_REQUIRED_CANDIDATE`, `FAILED_CLEANUP_INCOMPLETE_CANDIDATE`, `EVIDENCE_INVALID_CANDIDATE`, `EVIDENCE_RECONCILIATION_STARTED`, `COMPLETE_CANDIDATE`, `DEPENDENCIES_MISSING_EXECUTION_BLOCKED`, `COMPLETE`, `FAILED_PREMUTATION`, `FAILED_CLEANUP_REQUIRED`, `FAILED_CLEANUP_INCOMPLETE`, `EVIDENCE_INVALID`.

Terminal states are exactly `DEPENDENCIES_MISSING_EXECUTION_BLOCKED`, `COMPLETE`, `FAILED_PREMUTATION`, `FAILED_CLEANUP_REQUIRED`, `FAILED_CLEANUP_INCOMPLETE`, and `EVIDENCE_INVALID`. A terminal state is entered only after its terminal commit has been published and reread successfully. No terminal state transitions outward.

## 9. Hash authority and acyclic dependency DAG

Leaf artifact hashes cover their complete canonical bytes. Aggregate projections are exact:

- `artifact_registry_hash`: complete canonical artifact-registry bytes.
- `evidence_inventory_hash`: complete canonical evidence-inventory bytes.
- `precommit_control_inventory_hash`: complete canonical control-inventory bytes.
- `reconciliation_result_hash`: complete canonical reconciliation bytes. Reconciliation has no replay-snapshot or prepublication field.
- `replay_snapshot_hash`: complete canonical replay-snapshot bytes.
- `final_summary_hash`: canonical projection of final-summary fields 1-24 in the exact section 7 order, excluding only field 25 `commit_record_hash`.
- `prepublication_verification_hash`: complete canonical prepublication-verification bytes.
- `commit_record_hash`: complete canonical selected terminal-commit bytes; neither commit schema contains this hash.
- `final_summary_artifact_sha256`: complete canonical 25-field final-summary bytes including `commit_record_hash`.

The PRECOMMIT transition ledger stops at the selected candidate state and contains no terminal transition. The selected terminal commit contains the sole exact terminal transition as `state_before,state_after,reason_code`. Replay concatenates the validated PRECOMMIT rows with that commit transition in memory; it never rewrites the ledger.

The sole dependency order is:

`source evidence/ledgers -> precommit redaction -> three-row ledger binding set -> descriptor-only artifact registry -> hash-bearing evidence inventory -> precommit control inventory -> reconciliation -> Engine-owned terminal projection -> Engine-owned expected final-summary projection -> expected final-summary hash -> replay snapshot -> prepublication verification -> terminal-commit candidate -> complete final summary -> final in-memory redaction/set validation -> commit publication/reread -> in-memory replay authority`.

The Engine-owned expected final-summary projection depends only on immutable Engine state, the Engine-owned terminal projection, validated reconciliation, admitted artifacts, artifact registry, inventories, ledger bindings, recursive-redaction result, and lifecycle evidence. It explicitly excludes replay snapshot, prepublication verification, terminal commit, commit hash, publication receipt, and postpublication replay result. Replay snapshot and prepublication verification may bind the expected final-summary hash only after that hash exists.

No edge points backward. Reconciliation does not reference snapshot, prepublication, summary, or commit. Expected-summary construction does not reference snapshot or prepublication. Snapshot references reconciliation and the expected-summary hash but not prepublication or commit. Control inventory excludes itself and every later artifact. Prepublication references reconciliation, snapshot, and expected-summary hash but not itself or commit. Complete summary is staged before commit publication. No persisted artifact is written after terminal commit publication. This graph has zero directed cycles, zero self-references, and zero future-artifact dependencies.

## 10. Construction and publication authority

The exact construction order is:

1. Admit profile source artifacts and the three PRECOMMIT ledgers; the transition ledger ends at a candidate state.
2. Construct precommit redaction over exactly the present source artifacts and ledgers.
3. Construct the three-row ledger binding set, descriptor-only artifact registry, and then hash-bearing evidence inventory.
4. Construct `PRECOMMIT_CONTROL_INVENTORY_V1` over exactly its four earlier control members.
5. Construct reconciliation and require the profile's exact result.
6. Construct expected final-summary source fields with `expected_final_state`, `expected_final_result`, `expected_classification`, and the frozen expected marker; compute `final_summary_hash` without `commit_record_hash`.
7. Construct replay snapshot from facts known through step 6.
8. Construct prepublication verification over exact PRECOMMIT membership: profile members plus control inventory, reconciliation, and replay snapshot. Its certified count is profile count plus 3. It excludes itself, final summary, and terminal commit.
9. Construct the selected terminal commit with its exact terminal transition, `commit_created_utc` supplied by the engine clock before serialization, and both marker fields equal to the frozen marker; compute `commit_record_hash`. Filesystem publication timestamps have no cryptographic authority.
10. Construct complete final summary with that commit hash and compute its artifact hash.
11. Construct in-memory publication plan, final redaction result, and prepublication-set validation result. `authoritative_to_publish` is true iff every Boolean is true.
12. Stage and reread all persisted noncommit members, including final summary. Any collision or mismatch forbids publication.
13. Publish the terminal commit last, create-once.
14. Perform in-memory reread. Marker equality and terminal transition are verified here.
15. Derive terminal authority and replay in memory. No write occurs after step 13.

`PREPUBLICATION_SET_VALIDATION_RESULT_V1` is derived solely from validators for the named records. It is not persisted or hashed. `PUBLICATION_PLAN` is derived solely from profile paths plus the fixed derived/final/commit paths. It is not persisted or hashed.

## 11. Terminal and replay authority

- Success: valid success commit + complete summary + authoritative reread yields `COMPLETE`.
- Premutation or confirmed rollback: valid failure commit + complete summary + authoritative reread yields `FAILED_PREMUTATION`.
- Cleanup-required/incomplete paths require a valid failure commit and yield their named terminal state.
- Any structural, hash, inventory, marker, binding, redaction, reconciliation, publication, or replay defect yields a valid evidence-invalid failure commit where publication is still possible; otherwise no terminal authority exists until safe recovery constructs one.
- Commit absent, including summary-only residue, yields no terminal authority.
- Valid commit with missing/invalid summary, tampered commit, wrong marker, or invalid binding yields `EVIDENCE_INVALID` on replay.
- A terminal result, once published and reread, never mutates. Recovery restores the prior revision or publishes no additional record.

Replay reads persisted profile members, control inventory, reconciliation, replay snapshot, prepublication verification, complete summary, and terminal commit separately. It reconstructs identity, classification, transitions, profile, inventories, hashes, and marker equality. It never accepts caller terminal fields, environment facts, rewritten snapshots, postpublication receipts, or original-run memory.

Crash policy is exact: before commit publication, delete only uncommitted staging and retry with the same run ID if inputs are identical; collision means stop. During atomic commit creation, reread the target: absent means no authority and retry create-once; exact valid bytes mean authority; any other bytes mean evidence invalid and stop. After commit publication, no recovery write is allowed; replay decides authority.
