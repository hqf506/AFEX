# A2.4D Provider Evidence Normalization

Status: NORMALIZED; PROJECT-SPECIFIC AUTHORITY STILL UNRESOLVED

## Documented facts retained from supplied evidence

- Vercel recommends Supabase Transaction Pooler rather than unbounded direct PostgreSQL traffic for serverless workloads.
- Vercel recommends one bounded process-global `pg` pool and supports `attachDatabasePool` for lifecycle handling.
- Persistent prepared statements, persistent temporary-table state, and notification listeners are unsuitable for transaction pooling.
- Outbound PostgreSQL use from Vercel Node Functions is contemplated by the supplied Vercel guidance.
- PostgreSQL supports exact-signature EXECUTE ACLs and SECURITY DEFINER functions; these generic capabilities are not hosted-project authority.

## Project-specific inference

- Direct exact-signature EXECUTE is a smaller privilege graph than SET/role-switch architecture.
- A dedicated disposable LOGIN and owner would be operationally safer if the hosted platform supports them.
- The selected pool must be finite and fit measured project headroom.
- None of these inferences is provider support or runtime evidence.
