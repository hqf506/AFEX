## Test strategy

### Unit and type tests

- Field provenance and forbidden browser fields.
- Canonical payload/fingerprint golden vectors.
- Narrow facade has no generic methods.
- Exhaustive disposition/error mapping; unknown values fail.
- Redaction and stable-key lifecycle.
- Compile-time server-only/import-boundary tests.

### Mocked driver tests

- Launch/configuration failure, nonzero database error, timeout, cancellation, malformed result, and cleanup failure.
- No retry with a new key.
- No legacy fallback after send/acceptance ambiguity.
- No payload, key, token, or connection secret in logs.

### Isolated database/connection tests

- Exact function signature/EXECUTE-only attestation.
- Concurrent identical submissions and fingerprint conflict.
- Timeout after commit followed by same-key resolution.
- Cross-tenant, cross-branch, forged actor, inactive actor, and POS-actor mismatch.
- Reused connection after success, SQL error, rollback, timeout, cancellation, and process interruption.
- Role reset, search path, row security, custom GUC, prepared statement, and temporary-state contamination.
- Service-role credential cannot enter the trusted interface.

### Deployment tests

- Vercel cold/warm concurrency and connection caps.
- Saudi latency and timeout budget.
- Capacitor duplicate tap, offline draft, network loss, resume, and same-key retry.
- Secret availability/rotation without exposure.
- Disabled gate preserves the current route byte-for-behavior contract.

## Enablement controls

Startup validation is mandatory when the future gate is true. The first unsafe or missing setting stops trusted-client initialization. Enablement requires explicit environment approval; development/preview cannot infer Production permission. No route imports the trusted module until the import graph, rollback decision, and cutover plan pass review.

## Migration rules

- Preserve current Production path until an approved cutover.
- Do not dual-write legacy and Core V2.
- Do not shadow-mutate.
- Do not fallback to legacy after Core V2 send, acceptance, timeout, or unknown outcome.
- Rollout router selects exactly one engine before mutation and records that choice safely.
- Notifications/receipts move only when committed-result/outbox contracts exist.

## Review and approval chain

Security owner → database owner → application owner → platform/Vercel owner → Supabase/provider owner → release authority. Organizational approval cannot substitute for missing technical evidence.
