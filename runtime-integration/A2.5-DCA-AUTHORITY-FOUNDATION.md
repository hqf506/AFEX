# A2.5 DCA Provider-Neutral Authority Foundation

Status: `FOUNDATION_IMPLEMENTED`; `PARTIAL_EVIDENCE_PRODUCED`; `RUNTIME_PROOF_REQUIRED`; `CLOSURE_REVIEW_REQUIRED`.

This foundation implements the approved Option A object separation without choosing an external provider and without enabling a Docker mutation path. It does not approve the legacy Draft, authenticate a human, prove current host provenance, or grant execution authority.

## Object boundaries

The machine schemas keep these closed objects separate: immutable authority payload, terminal authority object, lineage event, fresh current-authority evidence, one-use runtime observation, separate execution authorization, durable consumption/action result, and non-authoritative generated-view metadata. Approval attestations remain detached from the terminal object's committed bytes. Dynamic currentness and revocation evidence are never embedded into the immutable terminal object.

Canonicalization is pinned to `A2.5-DCA-C14N-1`, SHA-256 is the only digest algorithm, JSON strings must be NFC without control characters, numbers must be safe integers, keys are sorted for canonical bytes, and authority-controlled identity arrays are strictly sorted and duplicate-free. The strict JSON parser rejects duplicate names before object interpretation.

## Authority separation

Digest verification proves byte commitment only. It does not prove approval authenticity. Terminal approval does not imply currentness. Currentness does not imply execution authorization. Generated Markdown has no independent authority. Execution authorization is a separate one-use object whose success requires provider evidence that this foundation intentionally cannot fabricate.

## Provider boundary

Host provenance, threshold approver authentication, trusted time, lineage/current pointer, revocation, execution authorization, durable audit/consumption, and the atomic executor are provider-neutral capability boundaries. Every unconfigured capability uses an unavailable adapter that always fails with `PROVIDER_UNAVAILABLE`.

## Permanent verification-only boundary

The engine validates authority, accepts read-only observations, and produces only a non-executable proposed intent. It exposes no mutation callback, Docker command builder, generic executor, operation-specific executor, dynamic mutation hook, or manual-execution transition.

`O10AStatus = ENGINE_DOCKER_MUTATION_PROHIBITED`

Real mutation is outside this engine and requires separate human authority. This does not replace or weaken O10-A to O10-B.
