# A2.3E Evidence Normalization and Architecture Gates

## Normalized evidence schema

| Field | Contract |
|---|---|
| evidence_id | Unique immutable evidence identifier |
| provider | `SUPABASE`, `VERCEL`, `AFEX_LOCAL`, or other approved source |
| category | Evidence class from the acquisition guide |
| field | Stable checklist field identifier |
| reported_value | Masked, non-secret scalar or short statement |
| evidence_source | Safe page/document/case/test reference |
| environment | Production, Preview, Development, isolated test, or provider-general |
| captured_at | UTC timestamp |
| sensitivity | PUBLIC, INTERNAL, or RESTRICTED; secrets are prohibited |
| confidence | HIGH, MEDIUM, LOW, or UNKNOWN |
| status | One allowed status below |
| blocker_mapping | One or more of G1–G12 |
| notes | Non-secret qualification or contradiction detail |

Allowed statuses only: `PROVEN`, `REPORTED_NOT_VERIFIED`, `NOT_AVAILABLE`, `SUPPORT_CONFIRMATION_REQUIRED`, `RUNTIME_TEST_REQUIRED`, `CONFLICTING`, `BLOCKING`, `NOT_APPLICABLE`.

## Fail-closed gate matrix

| Gate | Required evidence | Pass | Fail | Unknown | Architecture consequence |
|---|---|---|---|---|---|
| G1 Dedicated LOGIN | Supabase role support | Supported for custom LOGIN | Prohibited | No scoped answer | Transaction-pool candidate blocked |
| G2 SET-only membership | SET=true, INHERIT=false, ADMIN=false support | Exact membership supported | Any option unavailable | Not proven | Transaction-pool candidate blocked |
| G3 Transaction pinning | Provider confirmation plus isolated test | One backend for entire explicit transaction | Backend may change | Provider-only or absent test | Transaction pooling not approved |
| G4 Scoped activation | Role identity before/during/after test | Activation contained to transaction | Leaks or cannot activate | Not tested | Transaction pooling not approved |
| G5 Cleanup safety | Cleanup guarantee and contamination tests | No state survives return/reuse | State leakage | Guarantee/test missing | Pool topology blocked |
| G6 TLS/network | Address family, TCP, TLS, certificate evidence | Compatible secure path | No compatible secure path | Any component unknown | Selected topology blocked |
| G7 Vercel Node runtime | Runtime/version/TCP compatibility | Supported runtime and client | Unsupported | Version or support unknown | Direct Vercel path deferred |
| G8 Capacity | DB/pool limits, workload peak, pool sizing | Reviewed headroom exists | Limits below safe demand | Usage or limits unknown | Load-bearing rollout blocked |
| G9 Secret lifecycle | Scope, encryption, rotation, revocation approval | Approved Production-only process | Unsafe exposure/process | Process incomplete | Credential provisioning blocked |
| G10 Cancellation safety | Cancellation/disconnect/unknown-outcome tests | Rollback/recovery contract proven | Orphans or ambiguous unsafe recovery | Tests missing | Runtime cutover blocked |
| G11 Advisory locks | Provider semantics and isolated tests | Transaction-lock behavior matches contract | Unsupported/unsafe | Not tested | Current acquisition topology blocked |
| G12 Observability | Exit/error/connection/latency evidence plan | Required signals retained safely | Failures invisible or secrets logged | Coverage unknown | Operational approval blocked |

## Evaluation

Each required evidence row must be `PROVEN` for a gate to pass. `REPORTED_NOT_VERIFIED` may support review but cannot replace a required runtime test. `CONFLICTING`, `BLOCKING`, or required `NOT_AVAILABLE` fails the gate. `SUPPORT_CONFIRMATION_REQUIRED`, `RUNTIME_TEST_REQUIRED`, or missing evidence keeps it unknown and therefore fail-closed.

Final outcomes are selected manually by approved reviewers from: `TRANSACTION_POOL_ARCHITECTURE_APPROVED`, `TRANSACTION_POOL_ARCHITECTURE_BLOCKED`, `DIRECT_CONNECTION_ARCHITECTURE_APPROVED`, `SEPARATE_COMMAND_SERVICE_REQUIRED`, `INSUFFICIENT_EXTERNAL_EVIDENCE`, or `CONFLICTING_PROVIDER_EVIDENCE`. No script or document auto-selects an outcome.
